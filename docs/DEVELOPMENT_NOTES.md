# Synth Riders Full Body

PC 版 Synth Riders 3.x の VRM アバターに、SteamVR / Unity XR のトラッカーを反映する MelonLoader MOD です。ゲーム中のノーツ判定やスコアには変更を加えません。MelonLoader 0.7.3、Unity 6000.3.13f1 の生成済み参照 DLL で Release ビルド済みです。**ゲームとVR機器のないPCで開発しているため、姿勢・UI・追跡復帰はゲームPCでの確認が必要です。**

## v0.45.0 — モデルの大きさに合わせた校正とカメラ検出

- 標準モデル・VRMを問わず、校正中に頭と左右足の高さの差をユーザーへ合わせ、モデル全体を均等に拡縮します。骨の比率は変えません。立った姿勢を確認してからサイズと位置を固定し、START時にも取り直します。トラッカーの装着位置やモデルの体型による差は残るため、足裏と床の厳密な一致を保証する処理ではありません。
- 基準姿勢を作るとき、`HumanDescription` の骨の位置で読み込み済みの骨の位置を上書きする処理を廃止しました。インポート時の単位や拡縮の違いで骨の長さが変わるのを防ぎ、骨の位置は読み込み時の値、回転は基準姿勢を使用します。同名で曖昧な骨や無効な回転は使用しません。
- 大きな選択中モデルは、頭がHMDから4m以上離れていても検出対象にします。校正失敗・キャンセルではサイズと姿勢を元へ戻します。成功後はシーン移動でも校正時の実寸を復元します。v0.44の「移動先サイズで目標を再計算」から変更しています。起動後は一度校正してください。
- カメラはゲームの画面出力先を優先し、標準の三人称・スイング・観戦・シネマティック・カスタムに対応する取得経路を追加しました。Cameraコンポーネントが無効でも、手動描画される有効なGameObjectのカメラは検出します。旧アクセサーが欠けた場合の取得経路も維持します。
- カメラ位置の水色の球とラベルを距離に応じて拡大し、`VISUAL OPTIONS` にカメラ名・左右／前後方向・距離を表示します。一人称・OFF・LIVの場合は理由を表示します。LIVのカメラには追加の球を出しません。描画はHMD用のレイヤーで行い、配信用カメラから除外します。

**確認方法:** DLLを更新し、大きかったモデルで `CALIBRATE FULL BODY` を開き、鏡へ向いて直立、両足を床に置いて校正してください。カメラはゲーム側を三人称表示にし、`VISUAL OPTIONS` → `Camera guide in headset: ON` を選びます。方向・距離を目安に水色の球を探してください。

ログに `Calibration size:` と `Capture camera diagnostics:` を追加しました。表示できない場合は、その起動の `Latest.log` で検出状態とHMDカメラの描画設定を確認できます。

Releaseビルドは警告・エラー0件。モデルの大小と再校正の計算、カメラ選択・旧アクセサー・LIV除外を含む2,180件のチェックと設定保存テストを実行済みです。カメラ選択テストは模擬シーンを使用しており、IL2CPP上の動作・姿勢・HMD描画は実機確認が必要です。

## v0.44.0 — シーン移動後の追跡復帰とUI拡大

- 今回の `Latest.log` はv0.42.0で、ステージ移動後のVRMサイズ変更（8.8%、7.8%、6.1%など）を理由に校正を破棄していました。同じVRMでは、保存した校正時の骨格姿勢・トラッカー姿勢から、そのシーンのサイズに合うIK目標を作り直します。
- 同じVRMの一時消失・再生成・IKの差し替えからも、初期化とサイズの安定を待って復帰します。現在のユーザーの姿勢を新たな基準にはしません。復帰用の基準姿勢は同じフレーム内で適用・復元するため、画面を開いたりTポーズを要求したりせず追従を再開します。
- シーンやHMDカメラの変更時は追跡空間とゲーム空間の対応も取り直します。SteamVRのHMD追跡が一時的に途切れただけでは校正を破棄しません。
- 校正の保持は現在のゲーム起動中です。**起動後は一度校正してください。** 別のVRM・異なる骨格への変更、部位の割り当て変更、縦横比の異なる拡縮、手動での再校正開始では新しい校正が必要です。SteamVRの原点や外部の空間合わせを変更した場合も再校正してください。
- 詳細UIはCanvas全体を25%拡大し、入口ボタンの方向でユーザーから水平距離1.15〜1.6mに固定します。入口ボタンは元のスコア表示位置を保ち、開いた時点の距離に応じて拡大します。ポインターの当たり判定も同じ拡大を使い、入口と詳細パネルが見かけ上重ならないよう配置します。頭の動きには追従しません。

復帰時はログに `Full body recovery queued:` → `Full body calibration restored:` を出します。復帰できず手動校正が必要な場合は `Full body recovery requires manual calibration:` に理由を記録します。読み込み中は一時的にゲーム標準の3点追跡になります。

Releaseビルドは警告・エラー0件、計算・互換性・シーン復帰・UI配置の2,099件のチェックと設定保存テストに合格しました。VR実機でのシーン移動、文字の見やすさ、姿勢は未検証です。

## v0.43.0 — 部位別の割り当てとStanding校正

- `LIVE TRACKERS` から推測した部位名を削除しました。取得元、個体番号、型名、シリアル、座標、速度、追跡状態を表示します。移動・回転した個体に `MOVING` が出ます。HMD・コントローラーも一覧に含め、同じ個体が両APIに見える場合は取得元別に表示します。
- 起動時・接続変更時の自動割り当てを廃止。`TRACKER ROLES` で部位を選び、動かして確認した個体を4秒以内に2回選んで確定します。12部位（頭、左右肘・手首、腰、左右膝・足首・足先）を設定できます。ページ送りで全項目・全個体を選べます。同じ個体を別部位へ選ぶと、以前の割り当てを解除して移動します。
- `AUTO` を2回押すと、空いている腰・足首・足先へ候補を設定します。鏡へ体を向け、足を軽く開いて立ってください。鏡が取得できない場合は視線の水平な方向を使います。頭付近の個体は除外し、判別できない部位は未設定にします。既存の割り当ては保持するため、誤った設定を自動で直したい場合は先にその部位の `CLEAR` を押してください。結果は必ず個体を動かして確認してください。
- **片足の足首・足先に別々の2台を使用できます。** 足首を位置の基準にし、校正済みの足先位置から足の向きを計算、足先ボーンへ回転を反映します。骨の長さは維持します。両方を使う側はVRMの足先ボーンがVRIKに登録されている必要があり、不足時は校正画面に理由を表示します。
- 頭・手首はVRIKの目標、肘・膝は曲がる位置の目標へ反映します。追加部位には初期化済みVRIKが必要です。未設定の頭・手はゲーム標準の追跡を使用します。割り当てた追加部位の追跡を失った場合は、その入力を解除してゲーム標準／推定へ戻します。足先だけを失った場合は足首で継続し、足首を失った場合に足先を勝手に足首へ切り替えることはしません。
- `Standing` ではVRMの腕を下げた基準姿勢、`T-pose` では両腕を水平に伸ばした基準姿勢を表示します。どちらも校正中は固定され、前回のIK姿勢を基準に取り込みません。
- 割り当ては全VRM共通で、シリアルがある個体は再起動後も復元します。シリアルのない個体は今回の起動中のみ有効です。旧設定の腰・左右足のシリアルを引き継ぎます。HMD装着の位置合わせ用トラッカーを腰に設定していた場合は手動で直してください。

SteamVRの異種コントローラーも手首・MODのUI操作用として選べます。**ゲーム本体のノーツ判定用コントローラー入力の置き換えは含みません。** 混在環境はSteamVR等で追跡空間を合わせてください。HMD装着トラッカーを利用した継続的な空間補正はこのMODでは行いません。

Releaseビルドと1,947件の計算・割り当て・互換性チェック、設定保存テストを実行済みです。[実機確認チェックリスト](../REAL_DEVICE_CHECKLIST.md) の「今回の優先確認」から確認してください。

## v0.42.0 — ログで確認した問題からの修正

- 提供ログは v0.40.0。4台のVIVE Trackerがあり、腰として床上約1.65mの入力を使用していました。HMD装着の追加トラッカーを最高位置として腰に選んでしまう自動割り当てを修正しました。新規の自動選択ではHMD付近を除外し、必要な候補が揃うまで待ちます。候補が多すぎる場合は `TRACKER ROLES` で指定してください。既に指定した個体は、ターン・屈伸・追跡喪失で入れ替えません。
- 校正成功時に腰・左右足のシリアル番号を共通設定へ保存。校正時に腰がHMD付近なら、standingでも失敗理由を表示します。以前にHMDトラッカーを手動保存していた場合は `TRACKER ROLES` で本当の腰を選んでください。
- `CustomCameraSettings.get_customCameraTransform()` の直接呼び出しを削除し、生成DLLで存在するメンバーを実行時に確認します。カメラガイドをOFFにした間は探索しません。ONではゲームのカメラ位置そのものに直径16cmの水色の球とラベルを表示します。LIVには追加しません。
- つま先ボーンがVRIKに登録されている場合、足首からつま先への位置・回転オフセットを校正し、正しいボーンに目標を渡します。従来は常に足首を渡していました。[VRIK公式の足目標仕様](https://www.root-motion.com/finalikdox/html/page16.html)に合わせた修正です。膝の制限を強める変更はありません。
- 校正ではゲーム標準の鏡を一時表示し、固定Tポーズに水色の骨格ガイド、実際の両手位置にピンクの輪を重ねます。鏡は成功後もパネルを閉じるまで残し、一時的に開いた鏡は終了時に戻します。鏡の新設・移動・拡大は行いません。鏡を取得できない場合は固定の正面案内を使います。
- 注視点・カウントダウン・姿勢の案内を、開いた瞬間の目の高さへ固定。25度を超えて見下ろし・見上げているサンプルは校正に使いません。腕の準備時間は従来どおり5秒です。
- 設定画面の `Waist` は校正時からの入力と目標の移動量、`Body IK` はソルバーの状態を表示。ログには入力座標、IK直後とMOD更新時の骨盤の差、更新回数・LOD・重みを追加しました。
- 腰・左右足の割り当て、影、VRM内ライト、カメラガイドは共通設定です。HMDでのVRM表示だけは引き続きVRM別です。

実機でのターン・鏡・カメラ表示は未検証です。現在の版では `TRACKER ROLES` の腰の個体番号を確認してから再校正してください。提供ログにはシーン移動前後でアバターのスケールが変わり、再校正が必要になった記録もあります。これは別の確認項目としてチェックリストに残しています。

## v0.41.0 のUIと校正方向

- `FULL BODY SETTINGS` と `CALIBRATE FULL BODY` は、スコアが表示される位置に置く独立したボタンです。ゲームのスコアパネルは位置参照だけに使い、表示・入力・親子関係を変更しません。
- VRM選択中は詳細画面を開いていても入口の2ボタンを表示します。詳細画面は入口の下側（入口が低い場合は上側）に開きます。`Close panel` は詳細画面・校正の案内だけを閉じ、入口の2ボタンは残します。プレイ中とVRM選択を離れたときは非表示にします。
- 校正の正面は、画面を開いた時点のプレイヤー位置から `Toggle mirror` の鏡へ向かう方向です。床に `FRONT` の矢印、その方向に小さな案内とカウントダウンを表示します。頭や設定画面の向きでは変更しません。鏡の参照を取得できない場合は開いた瞬間の水平な視線方向を固定し、`FRONT = ARROW` と明示します。ログの `Calibration front:` に取得元を記録します。

### v0.40.0 の姿勢・IK変更

- スコア表示位置を取得できないゲーム版ではメニュー横へ配置し、ログの `Full body menu placement:` に配置先を記録します。
- 校正画面では全身を基準Tポーズで固定します。VRMのHumanoid骨格定義を優先し、取得できないボーンだけ初回取得時の姿勢を保持します。Animator・VRIK・ルート制御を一時停止し、繰り返し校正しても前回のIK姿勢を基準として取り込みません。成功後に追従を再開し、キャンセル時は表示前の姿勢とコンポーネントの状態を復元します。`Calibration reference pose:` に基準姿勢の取得元を記録します。
- 腰の追跡中は、腰の位置・回転を基準にVRIKを解きます。頭から胴体への位置・回転補正、自動ルート回転、両手から胸への回転補正を無効にし、仮想胸目標にも頭や手の向きを加えません。頭と腕はゲームのHMD・コントローラー目標を使います。
- 腰の追跡喪失時はMODのルート制御を停止し、ゲームの元のIK目標と設定へ戻します。復帰時は元の校正を使って約0.3秒でフルトラの重みを戻します。片足だけの喪失ではその足のIK重みを0にし、腰ともう片足の追従を維持します。自動割り当て済みのトラッカーが消えても、別の個体を代わりに割り当てません。
- 標準の `PelvisRotationWeight` を `1.0` に変更しました。旧版の標準値 `0.35` は自動移行し、それ以外の手動調整値を保持します。既存の手動設定が1未満なら頭の回転と骨盤の制御が混ざるため、まず1で確認してください。

Releaseビルドとゲーム不要の回帰テストを実行済みです。ゲーム内の配置・モデルごとの姿勢は未検証です。[実機確認チェックリスト](../REAL_DEVICE_CHECKLIST.md) の2・3・6を優先してください。

### 過去の変更

v0.13.0 以降は校正終了前の約0.6秒間に得た安定した姿勢を平均します。姿勢が動いた場合は校正を失敗にして再試行を促します。校正ログにはアバターの頭と腰の距離、脚の長さ、VRIKの頭目標の有無、首の硬さを出力します。追跡喪失時は腰・足のIK重みを徐々に下げ、復帰時は徐々に上げます。追跡元がUnity XRとSteamVRの間で変わった場合は再校正画面を開きます。v0.14.0 ではVRIKのルート制御を腰・足目標に合わせて校正します。頭目標がないアバターではこの処理をスキップし、ログに理由を出します。v0.15.0 ではVRIKへの足目標の事前制限を外し、アバターの膝の曲がる方向を校正時に記録して弱い曲げ目標を追加します。v0.16.0 では膝目標に使う股関節の相対位置を校正時に固定し、IK結果が次フレームの膝目標へ戻る揺れを防ぎます。v0.17.0 では現在のVRMの腰ボーンを参照するVRIKだけを使用し、VRIK参照が入れ替わった場合も再校正します。v0.18.0 では設定画面を開いている間、腰・足・頭の目標とボーンの差をログに出します。v0.19.0 では腰の向きの回転を保ち、前後・左右の傾きだけ弱められるようにします。

v0.20.0 では校正時のHMDの上下向きを基準にし、大きく見上げたり見下ろしたりしたときは仮想胸目標の重みを徐々に下げます。

v0.21.0 では脚の長さを校正時に測り直し、校正後にVRMのスケールが5%以上変化した状態が2回続いた場合は再校正画面を開きます。校正ログの `Avatar fit:` にはモデルの頭から足までの高さと、HMDから足トラッカーまでの高さを記録します。

v0.22.0 ではフレーム更新中にエラーが発生しても追跡処理を永久停止せず、アバターのIK目標を片付けて約2秒後に再探索します。復帰後は再校正が必要です。同じエラーが繰り返される場合、詳細ログは最大30秒に1回に抑えます。

v0.23.0 では設定パネルとVRM選択画面のボタンの更新に失敗した場合、UIを片付けて約5秒後に作り直します。開いていた設定パネルは再表示を試みます。校正カウントダウン中のエラーではカウントダウンを中止します。

v0.24.0 では設定パネルの `Close` 行の視線判定を縦方向に広げました。パネル内の空白部分を見ながらトリガーを約1.25秒押し続けても閉じられます。校正カウントダウン中は空白部分での長押しを無効にしています。

v0.25.0 では仮想胸目標の位置を、校正時に記録した腰から胸への距離と向きで計算します。IK が前フレームに動かした胸ボーンを目標の基準に使わないことで、上体の揺れを抑えます。

v0.26.0 では校正画面の先頭にキャリブレーション操作を置き、校正待ちの間はVRMの両腕を水平に伸ばしてTポーズのプレビューを表示します。校正完了・画面を閉じたときには腕の姿勢を戻します。位置合わせマーカーはトラッカー確認画面でのみ表示します。

v0.27.0 では校正ボタンとパネルに六角形のネオン枠を加え、暗い紫色の背景、ピンクの主操作、シアンの情報見出しへ配色を調整しました。校正ボタンは準備状態と視線選択に応じて色が変わります。

v0.28.0 では Synth Riders の設定画面の参考画像に合わせて、紫の見出しタブ、濃紺の項目カード、鮮やかなマゼンタの校正ボタン、シアンの補助テキストへ調整しました。外枠のネオンは控えめにしています。

v0.29.0 では左右コントローラーでUIを直接指し、それぞれのトリガーでボタンを押せるようにしました。設定画面には左がシアン、右がマゼンタの指し位置を表示します。VRM選択画面の校正ボタンも直接指して押せます。コントローラーの姿勢が取得できない場合は従来の視線＋トリガー操作を使えます。スライダーはまだありません。

v0.30.0 ではXRデバイスが重複して見える場合でも、左右それぞれのグリップ入力だけで設定画面を開閉します。コントローラー姿勢の選択を維持し、追跡不能や不正な座標・回転を持つデバイスは姿勢入力から除外します。設定ファイルは一時ファイル経由で更新し、読み込み・保存に失敗しても追跡処理を継続します。破損した既存設定は上書きせず、その起動中だけ初期値を使用します。Tポーズ表示中にアバターが消えた場合やMOD終了時の後片付けも改善しました。

v0.31.0 では設定画面右下の `VISUAL OPTIONS` から、配信・録画用カメラの位置表示、VRM の影、VRM 内のライトをそれぞれ切り替えられます。カメラ位置の目印は HMD のカメラだけで描画し、ゲーム画面用カメラからは隠します。VRM の描画設定はアバター変更時と MOD 終了時に元へ戻します。

v0.32.0 では `VISUAL OPTIONS` に `VRM in headset` を追加しました。Synth Riders が持つ一人称視点での VRM 表示設定を切り替えるため、配信・録画用カメラの VRM 表示はそのまま維持します。VRM を読み込んでいない間は切り替えられません。

v0.33.0 では VRM 選択画面の校正ボタンを、メニュー表示中に目線を動かしても追従しない位置へ固定しました。校正パネルは開いた瞬間の水平な正面方向、目の高さに固定します。Tポーズ校正はボタンを先に押し、5秒のカウントダウン中に両腕を広げる流れに変更しました。正面は校正パネルの方向で、頭を少し動かしても判定軸は動きません。UIのポインターには OpenXR の照準ポーズを優先し、コントローラーを追跡中は視線による選択を無効にしました。

v0.34.0 では、校正開始時のHMD位置・向きから SteamVR トラッカー座標と Unity XR コントローラー座標をそれぞれゲーム空間へ固定します。頭を動かすたびにトラッカーのワールド座標を再計算していた影響を取り除きました。腰の位置は VRIK に最大重みで渡し、足を上げた際には校正時の脚の長さと足位置を基準に、届く範囲で脚を伸ばす補正を加えます。従来の設定ファイルの標準値 `PelvisPositionWeight=0.8` は `1.0` に移行し、手動変更値は保持します。VRの原点を再設定した場合は再校正してください。

v0.35.0 では、`VRM in headset` の選択をVRMごとに保存し、シーン切り替え後に読み込まれたVRMへ再適用します。影とライトの無効化はフルトラ用のAnimator検出とは独立してVRM本体へ適用し、シーン切り替え時に再探索します。各表示機能の更新エラーが別の表示設定を解除しないようにしました。

v0.36.0 では、校正パネルをVRM選択メニュー内だけで開けるようにし、シーン切り替え時には閉じます。トラッカーの役割変更は独立した `TRACKER ROLES` 画面に移し、同じ役割を4秒以内に2回選んだときだけ変更します。左側の重複したトラッカーモニター項目を削除し、右側の `LIVE TRACKERS` を残しました。配信カメラの位置表示は、手動描画で無効状態のカメラとLIVカメラも探索し、見つかった位置に立体マーカーを追加します。

v0.37.0 では、VRM選択画面の右側に `FULL BODY SETTINGS` と `CALIBRATE FULL BODY` の2つのボタンを配置しました。両手グリップ長押しで設定画面を開く操作を削除し、VRM検出時の校正画面の自動表示もやめました。校正が必要なときは校正ボタンを強調します。

v0.38.0 では、ロール設定画面のマーカー表示と校正状態のリセットを修正しました。設定を開いたトリガーを一度離すまで、追加のクリック・長押し操作を受け付けません。HMDカメラ消失時はUIとTポーズプレビューを閉じます。配信カメラの探索を定期的にやり直し、HMD以外のカメラ（無効状態で手動描画するカメラを含む）からガイド用レイヤーを除外します。古い校正サンプルや同一トラッカーの複数ロールへの重複割り当てでは校正を成功させません。

v0.39.0 では、VRMを動かす腰・膝の計算とVRIK連携を修正しました。深い前屈で腰の水平回転が180度反転する計算を置き換え、膝の曲がる方向は校正時の脚の向きから現在の脚の向きへ連続的に回します。VRIKを使わない場合の2-Bone IKも同じ膝方向を使い、股関節に近すぎる・遠すぎる足位置を、脚の長さと最大屈曲角に収まる位置へ補正します。

追跡喪失時はルート制御を即座に停止し、復帰時の姿勢で校正し直す処理を削除しました。ルート制御中はHMD方向による自動ルート回転との競合を抑えます。ゲーム側がVRIKのソルバーや目標を変更した場合は追従を停止して再校正を要求し、元の状態の復元はMODが変更したソルバーに対して行います。稼働中のVRIKに目標を設定できない間は `VRIK waiting` とし、ボーンへの直接書き込みを重ねません。

腰の水平回転、膝の方向、2-Bone IKの脚長・屈曲制限はゲーム不要の回帰テストで検証できます。

```powershell
dotnet run --project tests/AvatarPoseMath/AvatarPoseMath.csproj -c Release
```

数値テストは実際のVRIK実行順序やVRMごとの動きを検証するものではありません。実機ではチェックリストの「6. VRMの姿勢と追跡復帰」を確認してください。VRIKの `maxRootAngle`、膝の曲がる方向、目標・重みの仕様は [RootMotion公式ドキュメント](https://www.root-motion.com/finalikdox/html/page16.html) を参照しています。

## 前提

- PC 版 Synth Riders と、Quest 3 の HMD・トラッカーが表示される SteamVR
- MelonLoader 0.7.x（net6 / IL2CPP）
- SteamVR 上で利用できる腰・左足・右足のトラッカー
- ゲーム内で表示される、Humanoid リグを持つ VRM アバター

ゲーム開発者は Synth Riders 3.x で従来のフルトラッキング機能を無効化したと[説明しています](https://steamcommunity.com/app/885000/discussions/0/591764421283479167/)。この MOD はアバター表示に腰と足の姿勢を追加する独立実装です。

### Quest 3 と VIVE トラッカー

- **VIVE Tracker (3.0)**: [SteamVR ベースステーション 1.0 または 2.0](https://www.vive.com/jp/accessory/tracker3/)と各トラッカーのドングルが必要です。Quest 3 の追跡空間と Lighthouse の追跡空間は、[OpenVR Space Calibrator](https://github.com/pushrax/OpenVR-SpaceCalibrator)などでゲーム起動前に合わせます。
- **VIVE Ultimate Tracker**: HTC は Quest 3 などの SteamVR 対応 PC VR ヘッドセットを[公式にサポート](https://www.vive.com/us/support/ultimate-tracker/category_howto/can-i-use-the-tracker-with-other-headsets.html)しています。ベースステーションは不要ですが、PC に VIVE Wireless Dongle を接続し、VIVE Hub でペアリング・追跡マップ作成後、[VIVE Space Calibrator で Quest 3 と位置合わせ](https://www.vive.com/us/support/ultimate-tracker/category_howto/calibrating-the-trackers.html)をします。
- 3.0 と Ultimate の混在も、**3 台すべてが同一の SteamVR 追跡空間に揃い、SteamVR に汎用トラッカーとして姿勢が表示されれば**、メーカーに依存せず割り当てます。ただし混在実機での動作は未確認です。

MOD の 3 秒カウントダウンは SteamVR の追跡空間同士を合わせる機能ではありません。SteamVR 側の位置合わせを済ませてから、VRM アバターと腰・足トラッカーのオフセットを設定します。ゲーム PC の `MelonLoader/Latest.log` にある `Tracking source:`、`SteamVR devices:`、`Three trackers detected via SteamVR.` で取得状態を確認できます。

## ビルド

公開ソースには参照DLLを同梱しません。ゲームPCで生成した `MelonLoader/Il2CppAssemblies` と、同じ環境の `MelonLoader/net6` を準備してください。ゲームがない開発PCでの配置、Visual Studio向けの設定、別フォルダーを使う場合のプロパティは [ビルド手順](BUILDING.md) にまとめています。

出力DLLをゲームの `Mods` へ配置します。`openvr_api.dll` は通常SteamVRから自動検出します。配布物の作成は [公開・配布手順](PUBLISHING.md) を参照してください。

## ゲーム内設定

設定画面または校正画面を開くと、右側に検出したデバイスのライブ一覧が表示されます。部位の推測ラベルは表示せず、取得元、デバイス番号、型名、シリアル番号、X/Y/Z座標（m）、移動速度（m/s）、追跡状態を確認できます。6台以上の場合は右下の `Next tracker page` で全台を確認できます。座標は補正前の各取得元のトラッキング空間の値です。

VRM選択画面でスコアが表示される位置に、独立した `FULL BODY SETTINGS` と `CALIBRATE FULL BODY` の2つのボタンが表示されます。VRMメニューが開いている間、入口の2ボタンは固定位置に残ります。コントローラーで指してその手のトリガーを押すと、それぞれ設定画面と校正画面が開きます。校正画面では選択したモードの基準姿勢で全身を固定し、`FRONT = MIRROR` と床の矢印で正面を示します。鏡が取得できない場合は `FRONT = ARROW` です。部位の割り当ては `TRACKER ROLES` 画面で行います。校正完了で追従が始まり、`Close panel` で詳細画面と案内を閉じても入口の2ボタンは残ります。

校正画面の `Pose` 行で `T-pose` と `standing` を切り替えます。StandingではVRMと同じように腕を下げ、正面の目の高さの点を見ながら3秒間静止してください。初期値のTポーズ校正は次の順序で行います。

1. `TRACKER ROLES` で腰と左右の足首（足先だけに装着する場合は足先）を指定します。足首・足先の両方に装着する場合は別の個体をそれぞれ指定します。追加部位もここで設定し、両手にコントローラーを持ちます。
2. `FRONT = MIRROR` の鏡へ体と顔を向け、足を軽く開きます。校正画面を開くと標準の鏡を一時表示します。水色の骨格が固定Tポーズ、ピンクの輪が実際の手位置です。
3. `START T-POSE CALIBRATION` を押します。ボタンを押す時点では両腕を広げる必要はありません。
4. 5秒のカウントダウン中に両腕を左右へ水平に伸ばし、肩の高さで静止します。目の高さの点を見て、0秒まで姿勢を保ちます。点がオレンジなら同じ高さに出る案内に従ってください。足元を見る必要はありません。
5. `Calibration complete` と出たら `Close panel` を押します。入口の2ボタンは残ります。失敗した場合は画面下部の理由を確認して再試行します。

腰トラッカーが低すぎる、左右の足が逆、腕の幅・高さが合わない場合は理由を表示します。コントローラー姿勢を取得できないときは `standing` に切り替えられます。いずれのモードも0秒直前の安定した腰・両足トラッカーの姿勢とアバターの相対位置・向きを記録します。VRMファイル自体は変更しません。画面を開いた位置に立ち、床の `FRONT` 矢印の方向へ体を向けたまま校正してください。位置を移動した場合は入口の `CALIBRATE FULL BODY` を押して基準位置を取り直します。同じモデルの再校正には保存した同じ骨格姿勢を使います。完了後は画面を開いたままでも追従が始まります。

位置合わせを詳しく確認したい場合は `TRACKER ROLES` を開いてください。設定画面・校正画面のどちらから開いても、水色の球はトラッカー、黄色の球はアバターの腰・左右足を示します。校正画面では、腰トラッカーが両足トラッカーより低すぎる場合に高さの警告が表示されます。

`LIVE TRACKERS` は約7回/秒更新します。個体を動かしたり回したりすると `MOVING`、接続中でも姿勢を取得できない場合は `Tracking lost` と表示します。役割は `TRACKER ROLES` で確認します。どの画面でもコントローラーで `Close` 行を指してトリガーを押すか、約0.35秒押し続けると閉じます。行を狙いにくいときはパネルの空白部分を指しながら約1.25秒長押ししてください（校正カウントダウン中を除く）。

VRM選択メニューを開いている間だけ、スコア表示位置の `FULL BODY SETTINGS` ボタンから詳細設定を開けます。ゲームプレイ中にメニューは表示されません。操作したい行をコントローラーで指し、その手のトリガーを押します。コントローラーの姿勢が取得できない場合は視線を行に合わせてトリガーを押します。両手グリップ長押しはMODの画面操作に使用しません。

- `TRACKER ROLES`: 部位を選ぶと個体一覧へ進みます。対象の個体を動かして `MOVING` とシリアルを確認し、同じ個体を4秒以内に2回選んで確定します。`CLEAR / USE GAME DEFAULT` で解除できます。`AUTO` は腰・足首・足先の空き部位への候補設定です。頭・肘・手首・膝は手動で指定します。変更後は再校正してください。
- `CALIBRATE FULL BODY`: 上記のカウントダウン校正画面を開きます。
- `Tracking`: アバターへの反映をオン・オフにします。オフでも設定パネルは操作できます。

### `missing` と表示された場合

画面上部の `Unity XR` または `SteamVR` のトラッカー数と `HMD` を確認してください。Unity XR にトラッカーが表示されない場合、MOD は SteamVR の汎用トラッカーを直接取得します。まず SteamVR 上で Quest 3 と 3 台の VIVE Tracker が追跡中か、追跡空間が校正済みかを確認します。ゲーム PC の `MelonLoader/Latest.log` の `Tracking source:` 以下に `Unity XR devices:` と `SteamVR devices:` の両方が出ます。各行の `pose=no` はデバイス名が見えていても位置・回転が取得できない状態です。`SteamVR devices:` に `openvr_api.dll not found` または `OpenVR initialization` と出る場合は、SteamVR のインストールと起動状態を確認してください。

トラッカー数が 3 以上でも一部の役割が `missing` なら、VRM選択メニューで詳細設定を開き、`TRACKER ROLES` 画面で腰・左右足を割り当てます。ログを共有する際はシリアル番号を伏せても構いません。

### 校正完了後も追従しない場合

`MelonLoader/Latest.log` に `Full body calibration completed.` と `Avatar drive mode: VRIK targets` があるか確認してください。ゲームの VRIK コンポーネントが利用できれば、MOD は腰と両足の IK 目標を動かします。`bone fallback` の場合はアバターのボーンを直接動かします。VRIK がゲーム側に存在しても利用できない場合、ゲーム本体の更新順序によって直接操作が上書きされる可能性があります。アバターを選んでミラーを表示し、校正画面を開いたまま腰や足を動かすと追従を確認できます。

校正が成功した状態で設定画面を開くと、約2.5秒ごとに `Avatar pose diagnostics:` をログへ出します。`post-solve pelvis error` はIK直後、`late pelvis error` はMOD更新時の骨盤と目標の差です。`feet bone-target` は実際のVRIK終端（つま先があればつま先）と目標の距離です。`waist input/target travel` で校正からの入力・目標の移動量も確認できます。`head motion HMD/target/bone` は校正時からの回転変化量、`target-bone motion difference` は頭目標と頭ボーンの回転変化の差です。腰や頭を動かした後に約2秒静止して読むと、フレーム間の遅れが入りにくくなります。値にはアバター固有の姿勢差とVRIKの補正も含まれるため、単独の数値で正常・異常を判定しません。

`Avatar fit:` の `approximate ratio` はVRMの頭から足までの高さを、HMDから足トラッカーまでの高さで割った参考値です。HMDや足トラッカーの装着位置の差を含みます。同じVRMがシーン移動で均等に拡縮された場合は、保存した基準から目標を再構築して追従を再開します。異なる骨格や縦横比へ変更された場合は再校正が必要です。

選択したトラッカーのシリアル番号が得られる場合は `UserData/SynthRidersFullBody.json` に保存され、次回起動時にも使われます。シリアル番号が空のデバイスは現在のゲーム起動中だけ番号で固定されます。

## 配信カメラの位置と VRM の描画負荷

フルトラ設定画面右側の `VISUAL OPTIONS` を押すと、次の項目が表示されます。コントローラーで指してトリガーを押すか、視線とトリガーで切り替えます。キャリブレーションは不要です。

- `Camera guide in headset`: Synth Riders の配信・録画用 Custom Camera の位置に水色の球、その上に `CAPTURE CAMERA` を表示します。LIVの目印はLIV側を使います。手動描画で Camera コンポーネントが無効でも位置を取得します。空きレイヤーを使い、HMD 側だけで描画します。配信カメラが見つからないときは目印を隠します。
- `VRM cast/receive shadows`: `OFF` にすると、現在の VRM の Renderer が影を落とす処理と影を受ける処理を無効にします。ステージ全体の影は変更しません。
- `VRM lights`: `OFF` にすると、現在の VRM に含まれる Light コンポーネントを無効にします。VRM にライトがない場合は効果がありません。
- `VRM in headset`: HMD から自分の VRM を見るかどうかを切り替えます。Synth Riders のアバター設定を操作します。配信カメラの VRM 表示には影響しません。MODで切り替えた値はVRMごとに保存され、新しいシーンでVRMが読み込まれたときに再適用されます。

初期値は位置表示が `OFF`、影とライトが `ON` です。設定は `UserData/SynthRidersFullBody.json` に保存されます。描画負荷の改善量は VRM の Renderer・Light とゲーム側の描画方式によって変わります。素材やシェーダー自体の処理量は変えません。切り替え前後のフレーム時間はゲーム PC で確認してください。

## 設定ファイル

初回起動時にゲームの `UserData/SynthRidersFullBody.json` が生成されます。割り当てはゲーム内の `TRACKER ROLES` で設定します。ファイルで指定する場合は `RoleBindings` に部位名をキーとして `Source`（`SteamVR` または `Unity XR`）と `Serial` を記入します。例: `"LeftToes": { "Source": "SteamVR", "Serial": "実際の個体番号" }`。`LeftFoot` / `RightFoot` は足首を意味します。旧 `WaistSerial` / `LeftFootSerial` / `RightFootSerial` は、`RoleBindings` 自体がない旧ファイルからの初回移行でのみ使用します。同じ個体を複数部位に指定した場合は `CONFLICT` と表示し、校正を止めます。

```json
{
  "RoleBindings": {},
  "Enabled": true,
  "ShowCaptureCameraGuide": false,
  "DisableAvatarShadows": false,
  "DisableAvatarLights": false,
  "SmoothingEnabled": true,
  "PositionMinCutoffHz": 2.5,
  "PositionBeta": 3.0,
  "RotationMinCutoffHz": 2.0,
  "RotationBeta": 1.0,
  "PelvisMaxTiltDegrees": 20.0,
  "PelvisTiltWeight": 0.5,
  "PelvisPositionWeight": 1.0,
  "PelvisRotationWeight": 1.0,
  "UseVrikRootController": true,
  "ChestGoalWeight": 0.15,
  "ChestHeadDirectionWeight": 0.0,
  "ChestHandDirectionWeight": 0.0,
  "KneeMaxFlexionDegrees": 145.0,
  "KneeBendGoalWeight": 0.3,
  "CorrectionVersion": 4
}
```

VRM を選択・変更すると校正が必要な状態になり、VRM選択画面のスコア表示位置の `CALIBRATE FULL BODY` ボタンが強調されます。校正画面はこのボタン、または `FULL BODY SETTINGS` の `CALIBRATE FULL BODY` から開きます。アバターごとの初回校正は必須です。カウントダウンが成功するまでトラッカー姿勢をアバターに反映しません。

`UseVrikRootController` は、VRIK のルートを腰・足の目標と整合させる補正です。ゲーム側に同コンポーネントが既にあれば再校正し、なければ追加します。追跡が消えたときは停止し、MOD の目標を外すときは追加したコンポーネントを破棄して元の状態に戻します。ゲーム側との競合が見られる場合は `false` に設定して再起動できます。`Avatar rig:` の `rootController` と `rootControlActive` に実際の状態が出ます。

腰・足の入力位置と回転には [1€ Filter](https://gery.casiez.net/1euro/) を適用します。LIVE TRACKERS は補正前の座標を表示します。Position/Rotation の MinCutoffHz を小さくすると静止時の揺れは減りますが追従が遅れ、Beta を大きくすると速い動きでの遅れが減ります。PelvisTiltWeight は腰トラッカーの前後・左右の傾きを反映する割合で、初期値は 0.5 です。0 では腰の向きの回転だけを使い、1 では傾きをそのまま使います。PelvisMaxTiltDegrees は反映後の傾きの上限です。PelvisPositionWeight と PelvisRotationWeight は VRIK の骨盤位置・回転の重みです。KneeMaxFlexionDegrees は骨を直接動かす代替モードでのみ使います。腰トラッカーの傾きは骨盤の回転には使いますが、腰位置の校正オフセットは水平方向にのみ回します。VRIK 使用時は計測した足の目標をそのまま渡し、既存の膝曲げ目標がない脚には校正時の膝の向きを弱い曲げ目標として渡します。KneeBendGoalWeight はその強さで、0 にすると追加しません。既にゲーム側の曲げ目標がある場合は維持します。古い設定ファイルで旧初期値と一致する補正項目は新しい値に一度だけ更新され、それ以外の値は維持されます。設定値の変更後はゲームを再起動します。Quest 3 と VIVE Tracker の追跡空間の位置合わせは SteamVR 側で行います。

胸トラッカーがないため、胸ボーンを持つVRMでは腰の補正後の向きと校正時の腰から胸へのオフセットから仮想胸目標を作ります。腰を追跡中だけ使用し、腰の喪失・追従OFF・MOD終了時はゲーム側の胸目標を復元します。ログのドライブモードが `VRIK targets + virtual chest` の場合に有効です。`ChestGoalWeight` を0にすると追加しません。`ChestHeadDirectionWeight` と `ChestHandDirectionWeight` は旧設定の読み込み互換用として残っていますが、現在の仮想胸には使用しません。実際の胸の独立した動きは推定できません。

## 動作と制限

- Unity XR に出ないトラッカーは SteamVR の OpenVR API から取得します。SteamVR に Quest 3 の HMD と 3 台の汎用トラッカーが姿勢付きで公開される必要があります。`MelonLoader/Latest.log` の `SteamVR devices` で確認できます。
- 初回のフルトラ校正には腰・両足の3台が必要です。校正後の腰喪失時はゲームのIKへ戻し、片足だけの喪失では腰の追従を継続します。
- アバターの腰と脚を後段で操作します。ゲーム本体の IK 更新順序やアバターのボーン構造によっては姿勢がずれる可能性があります。
- Quest 単体版や PlayStation 版は対象外です。
