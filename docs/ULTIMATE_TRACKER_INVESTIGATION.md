# Ultimate Trackerでの校正失敗の調査

対象：提供されたv0.45.0・v0.46.0・v0.48.0のログと、その後の移動方向の報告。現在の変更版：v0.49.0。

## v0.49.0：向きの補正後に残った大きな水平位置ずれ

`Latest (1).log` はv0.48.0で、180度補正ON・Tポーズ校正成功3回の記録がある。最初の左右逆警告の後、部位を割り当て直した20:26:07と20:32:43の校正では、符号付き足幅が正になっている。後半の校正時は3台とも `Running_OK`。

| 時刻・項目 | ログの値 | 読み取れること |
| --- | --- | --- |
| 20:26:07 校正時の頭／腰 | 頭 `(0.048, 1.626, -0.103)`、腰 `(1.393, 0.928, -0.432)` m | 補正後も頭と腰に約1.38mの水平ずれがある。 |
| 同じ校正の骨盤 | `(0.11, 1.04, -0.07)` m | 腰入力とモデル骨盤の間に約1.33mの水平オフセットが残る。 |
| 20:25:38 腰入力／骨盤目標の移動 | `0.104 / 0.411` m、入力回転16.1度 | 並進だけでなく、回転する校正オフセットが目標の移動へ加わっている。 |
| 20:32:55 足ボーンと目標の差 | 左0.779m、右0.105m | 足のIK目標へ届いていない。入力移動量そのものはこの版には記録されていない。 |
| 20:26:07 モデルとユーザーの高さ | モデル頭～足1.484m、HMD～足トラッカー1.569m | この校正のサイズは何倍もの拡大ではない。 |

### コード上の原因と修正

v0.48.0の補正は腰を回転中心にして水平180度回転するため、腰の位置そのものは移動しなかった。その一方、モデルはHMD側へ配置される。残った空間の共通の位置ずれは、腰・足から各ボーンまでの装着オフセットへ混入し、足首の傾きや腰の旋回で長いレバーのように回転していた。姿勢フィルターを強めてもこの幾何学的なずれは取り除けない。

v0.49.0では、腰が補正対象のUltimate Trackerなら、校正開始時の腰の水平位置をHMDの真下へ合わせ、同じ平行移動を対象の全機器に適用する。高さ・機器間距離・移動量の倍率は変更しない。基準は生の追跡空間に固定し、通常追跡やシーン復帰で頭に追従させない。腰が対象外・未追跡なら従来の回転補正だけを行う。

これは直立校正時の頭と腰の水平位置が近いことを利用した近似であり、外部の空間校正を厳密に再現するものではない。腰・足の実際の装着位置や体格差の残差は既存の校正で扱う。今回の大きな回転オフセットは確認できたが、報告されたI字姿勢の全経過や実機での解消は未確認。

共通の移動は `shared shift`、残った装着オフセットの長さは `rotating offsets waist/left/right` に記録する。動作中の `Avatar pose diagnostics` に左右の入力／IK目標の移動量と位置も追加した。設定画面を開いたまま横移動・足首の傾き・腰の回転を別々に行うと、どの段階で動きが大きくなったかを切り分けられる。

## v0.48.0：前後・左右がともに逆の環境向けの180度補正

追加報告では、左足と右足の個体は対応しているが、前後だけでなく左右へ移動する方向も逆だった。この症状と以前の負の足幅は、HMDとUltimate Trackerの追跡空間に水平180度の向きの差がある場合と整合する。ただし、実機で座標を同時計測していないため原因の確定ではない。

`SteamVrTracking.TryPose` の標準変換は下記Valve実装と一致することを再確認した。機種全体の座標仕様が逆という根拠はなく、補正は初期値OFFの環境別設定 `UltimateTrackerRotate180` として追加した。

- ゲーム内の `FULL BODY SETTINGS` → `Ultimate 180 correction: ON` で有効化し、再校正する。
- SteamVRが `VIVE Ultimate Tracker` またはその名前に番号などが続くモデルとして報告し、種別がTrackerの機器だけへ適用する。
- 生座標の固定中心の周りで、位置と回転へ同じ180度の剛体変換を適用してから、ゲーム座標へ移す。機器の装着軸や左右の役割を交換しない。
- 中心は取得可能な対象の腰、なければ最初の対象機器の位置。最初の姿勢読み取りで固定し、再校正開始時に取り直す。その後の頭や腰の動きで中心を更新しない。
- 補正は主入力・追加部位・AUTOの候補位置に共通で使用する。HMD原点、Questコントローラー、VIVE Tracker 3.0、LIVE TRACKERSの生座標は変更しない。
- シーン復帰では生の追跡空間の補正を保持し、ゲーム空間への原点変換だけを更新する。補正設定の変更は旧校正・フィルター・保存セッションを解除する。
- ログには補正状態、対象台数、固定中心、各部位への適用有無と生／ワールド座標を残す。

前後だけの反転はこの180度補正の対象外。実機で有効化して再校正した後、前後・左右・上下、腰・足の回転、旋回とシーン移動を確認する。

## v0.47.0：足の配置チェックを警告へ変更

追加ログ `26-10-12_16-47-25.log` では、v0.46.0のTポーズ2回・Standing2回とも `Feet reversed vs FRONT` で停止していた。正面との内積は0.999～1.000、符号付き足幅は約-0.191～-0.225mで、正面を向いた状態でも負の足幅だった。5台のUltimate Trackerは `Running_OK`。生座標の段階でも左右足の順序が逆で、実物との対応や空間合わせが正しいかはログだけでは断定できない。

ユーザーの指定により、左右逆と足幅不足は校正を停止しない警告にした。Standing・Tポーズの両方へ適用する。足幅不足は距離の絶対値で判定し、十分に離れた逆配置に足幅不足の警告を重ねない。

警告はカウントダウン中と完了後のUI、および完了判定時の `Calibration posture warning (non-blocking):` ログに表示する。左右の自動交換や追加確認操作は行わない。追跡・正面・視線・腰の高さ・静止状態・Tポーズの腕・アバターの条件は維持する。

## v0.45.0のログで確認できたこと

- Quest 3、左右のQuestコントローラー、Ultimate Tracker 5台をSteamVRから取得していた。
- Ultimate Trackerはログ上、5台とも姿勢取得に成功している。右コントローラーは断続的に姿勢を失っていた。
- 校正失敗19回のうち18回は `left/right foot trackers swapped`、1回は `waist tracker too low`。成功記録はない。
- 足首から足先への割り当て変更、TポーズからStandingへの変更後も同じ左右の判定で停止していた。
- 最後は腰・左右足首・左右膝を割り当てていた。初期には後から左膝へ割り当てた個体が左足首に選ばれていたが、その後も失敗しているため、これだけを全体の原因とは断定できない。

これらの失敗はアバターのIKを確定する前の姿勢チェックによるもの。検出失敗やUltimate Trackerの機種名の拒否ではない。失敗時の実座標・視線方向が旧ログに含まれないため、実物の左右、追跡空間、MODの基準方向のどこで不一致が生じたかは未確定。

テスト担当者の環境であり、SteamVRや別アプリでの実物との位置一致は確認できていない。利用者側の誤操作を前提にはしない。

## 実装と一次資料の確認

### OpenVRからUnityへの変換

`SteamVrTracking.TryPose` の位置・前方・上方ベクトルの符号は、[ValveのSteamVR Unity PluginのRigidTransform](https://github.com/ValveSoftware/steamvr_unity_plugin/blob/master/Assets/SteamVR/Scripts/SteamVR_Utils.cs) と対応している。トラッカーの機種による分岐はない。Ultimate Trackerにだけ180度回転や左右交換を加える根拠は見つかっていない。

機器のローカルな装着軸と、追跡空間における位置は別の情報。今回の左右チェックは位置だけを使うため、装着回転が異なることだけでは左右判定の反転を説明できない。

### Ultimate Tracker側の位置合わせ

HTCは、マップ作成後にVIVE Space Calibratorでコントローラーとトラッカーの位置合わせを行う手順を案内している。[公式校正手順](https://www.vive.com/us/support/ultimate-tracker/category_howto/calibrating-the-trackers.html)

また、VR内の位置が実物と一致しないときの対処として追跡の再取得を挙げ、別の空間補正ツールとの同時使用が位置合わせに影響すると説明している。[公式トラブル対処](https://www.vive.com/ca/support/ultimate-tracker/category_howto/tracker-position-in-vr-and-real-world-dont-match.html)

これは今回の原因の確定ではなく、調査対象の一つ。MODがHMDから求める変換は「各APIの空間→ゲーム空間」であり、HMDとトラッカーの間にある外部の位置合わせの誤差を自動修正するものではない。

## v0.46.0で修正した内容

1. **正面・視線を先に確認。** 旧版は固定正面に対する足の左右を先に判定していたため、背を向けていると正しく割り当てた足も「逆」と表示された。先に正面へ向く案内を出す。
2. **原因を断定しない表示。** 正面を向いた状態で足幅が負なら、割り当てと空間合わせの両方を確認する案内にした。自動で左右を入れ替えたり、不正な配置をそのまま通したりはしない。
3. **Standingの共通チェックからT-pose表記を除去。** Standingでも腕のTポーズ判定をしているように見える問題を修正した。
4. **失敗時にも診断値を保存。** 校正開始・失敗・成功時に下記情報を記録する。
   - モード、正面の取得元、腰・左右足の追跡可否。
   - HMDの正面との内積、符号付き足幅、腰と平均足位置の高さの差。
   - HMD・腰・左右足のワールド座標。
   - API別の原点変換と、変換後HMDとゲーム内カメラの位置・回転の差。
   - 割り当てた全部位の個体・型名・生座標・ワールド座標・姿勢の軸。
   - OpenVRの接続フラグ、姿勢有効フラグ、追跡状態。

追加診断は開始・結果時だけに行う。診断中の例外は校正へ波及させない。v0.46.0では従来の足幅・高さ・静止条件を維持した。v0.47.0の足の配置チェックは上記の警告へ変更している。

## 次の実機確認

1. v0.49.0のDLLを配置し、ログの起動バージョンを確認する。前後・左右ともに逆の報告環境では `Ultimate 180 correction` をONにしてから、直立して校正する。
2. 可能なら、SteamVR内でUltimate Trackerの表示位置が実物と一致しているかを確認する。外部の位置合わせを修正した場合はMODでも再校正する。
3. MODで腰・左足・右足の個体を、1つずつ動かして確認する。追加の膝なども割り当て済みなら、その部位も追跡中であることを確認する。
4. 床のFRONT方向へ直立し、まずStandingで一度試す。成功すればTポーズでも確認する。足の左右逆・足幅不足が出ても、他の条件を満たせば成功し、完了後も警告が表示されることを確認する。
5. 失敗しても設定を何度も変えず、表示理由とその起動の `Latest.log` を共有する。

`Calibration check` の読み方（成功時・失敗時共通）：

| 値 | 意味 |
| --- | --- |
| `facing dot` | 1は正面、0は横、-1は逆向き。0.5未満では正面への案内を出す。 |
| `foot signed separation` | 正面を基準にした右足−左足の横方向距離。-0.05m未満なら逆配置、絶対値が0.08m未満なら足幅不足。v0.47.0ではどちらも警告のみ。 |
| `waist above feet` | 腰と平均足位置の高さの差。0.40m未満では直立・割り当て・空間合わせを確認する。 |

欠測フレームの座標は判定に使える値ではないため、最初に `tracked waist/left/right` を確認する。HMDの変換誤差が小さくてもトラッカーとの空間一致は保証されない。体型や姿勢を見ずに、数値だけで原因を確定しない。

## 検証範囲

v0.49.0では、新しいログの原点・生座標・骨盤位置を使い、共通の位置ずれを足や腰の回転オフセットへ混ぜる問題を回帰テストで再現した。足のボーン位置と後続の回転はログにないため、検証用の値を与えた。旧方式で足を傾けると1m超持ち上がる条件が、新方式では20cm未満の装着オフセットの範囲へ収まる。並進の等倍反映、高さの保持、機器共通の平行移動、原点の傾き、シーン復帰も含め、既存の2,475件のチェックに合格した。

v0.48.0では、機種の選別、前後・左右・上下の変位、原点の向き・傾き、装着軸が異なる足の回転とオフセット、シーン原点の再配置、提供ログの足の並びをテストした。既存テストと合わせて2,448件のチェックと設定保存テストに合格。Releaseビルドも警告・エラーともに0件で成功した。実機での補正効果は未確認。

v0.46.0では正面・逆向き・実際の左右逆・Standingでの手の欠測・Tポーズでの手の欠測・腰の高さ・不正な数値をテストした。プレイスペース全体の水平回転と平行移動を変えても、同じ判定となることを確認した。既存テストと合わせて2,250件のチェックに合格。

v0.47.0では、左右逆・足幅ゼロ・狭い正負の足幅・両警告の同時発生が校正を停止しないことを両モードで検証した。足の警告があっても追跡欠測・逆向き・Tポーズの手の欠測や低い腕を通過させないこと、および追加ログの身体座標が警告付きで通ることを回帰テストへ追加した。ログに手の座標はないため、Tポーズの再現テストでは有効な手の位置を補っている。既存テストを含む2,276件のチェックに合格し、Releaseビルドも警告・エラーともに0件で成功した。

ゲームとUltimate Trackerの実機での成功は未確認。今回の変更は確認できた判定・案内の不具合の修正と、原因確定に必要な計測の追加であり、Ultimate Tracker固有の問題がすべて解消したという結論ではない。
