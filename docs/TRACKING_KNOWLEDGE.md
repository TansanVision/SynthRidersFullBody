# トラッキング実装の共有メモ

更新: 2026-10-25 / Synth Riders Full Body v0.59.8。DanceDashなどへの移植用。実機で症状が解消したと確認できた事項と、コード・ログから確認できた不具合を区別する。以下の新規修正は数値・接続寿命のテストとビルドで検証し、ゲーム実機での確認は残っている。

### 固まったHMDを使う登録と曲間の不安定さ

- 13:46以降の校正診断26件でSteamVR HMDの生姿勢が同じ表示値 `(-0.216, 1.578, -1.284)` m、forward `(-0.012, 0.121, 0.993)`。同時にUnity XRのHMDは変化している。有効フラグだけでは新鮮な入力とは限らない。
- 最初のSteamVR原点のupは `(0.086, 0.851, 0.519)`。鉛直から約32度傾いている。旧処理は `cameraRotation * inverse(rawHeadRotation)` をそのまま原点に使い、頭の時間差・停止によるpitch/rollまで全トラッカーの床へ固定していた。
- シーンごとに各APIのHMDからこの登録を取り直していたため、固定されたSteamVR HMDと現在のUnity XR HMDの差が曲ごとに変化する。これは頭の状態で全身の姿勢が変わる具体的な経路である。
- v0.59.8では立位空間を位置とyawだけで合わせる。シーン復帰ではゲーム側XR原点の差分を全APIに一括適用し、API間の登録は保持する。`TrackingSpaceAnchor` / `LevelTrackingSpace` / `Tracking.RebaseWorldAnchors` を参照。
- 外部ランタイム側の停止、初回yawの誤登録、SteamVRだけの原点変更は別問題。水平化だけで全部が直るとは限らない。`HeadPoseFreshness` は片側HMDだけが1秒以上止まり、他方が動いたときに警告する。追跡や校正は自動拒否しない。
- 初回は足トラッカーの生Yが約-1.24m、その後は約0.07m。準備中の外部原点変化もあるため、全異常をIKだけの問題として扱わない。

### コントローラーの表情入力

姿勢が取れなくてもボタンは取れる場合がある。旧実装はUIポインターの選択結果と姿勢の有効性に表情入力を依存させていた。OpenVRのlegacyボタンAPIとゲームのOpenXRボタンAPIも同一ではない。

v0.59.8では表情をポインターから分離し、手首に明示割り当てしたコントローラーを優先、それがなければゲーム側XRでボタンを読める個体を優先する。左右それぞれの入力元を保持し、片手の再接続で他方の押下・保持表情を消さない。交換された側は一度離すまで発火しない。旧ログにはボタンの対応ビットがないため、右ボタン不検出の全原因を断定してはいけない。新しい `Expression input:` で取得元と対応ビットを追う。

## 姿勢とIKの原則

1. **不変の校正姿勢を保存する。** 同じVRMの再校正・シーン復帰で、直前にIKが曲げた姿勢やロード中のアニメーションを新しい基準にしない。骨の相対パス、ローカル位置と回転、実寸スケール、原点、頭・腰・足・追加部位の校正入力を値で保存する。
2. **HMD入力とゲームの中間目標を分ける。** 中間目標が停止するゲームでは頭を直接読む。復帰中に現在の首の傾きから校正オフセットを学習し直さない。明示的な頭トラッカーは別の入力として扱う。
3. **腰追跡が有効なら腰で骨盤を駆動する。** 頭による骨盤移動を併用して腰の実測を打ち消さない。腰欠測時はゲームの目標へ復帰し、回復時は短くブレンドする。
4. **追跡空間の登録と装着オフセットを分ける。** 空間同士の数十cmのずれを各関節の回転オフセットに吸収すると、回転時に大きな円運動になる。One Euro Filterを強めても幾何学的な誤差は解決しない。
5. **トラッカー、足首、IK終端、足先を区別する。** VRIK終端がToesでも、足首目標を同じ点として使わない。`TrackedFootPose` / `RigidPoseOffset` / `DualFootMath` を参照。独立した足先入力がある場合も足首位置を平行移動させない。
6. **到達不足と膝曲げを区別する。** 脚を伸ばすために推定した距離を無条件に足へ追加すると、実際の膝曲げが消える。上限99.9%の到達制限は、同じ長さの上下脚で約5.1度の曲げを強制する。v0.59.7は限界で解析的に伸ばすが、通常の短い目標では膝曲げを保つ。
7. **膝の曲げ面をモデルの固定ローカル軸で決めない。** 校正姿勢の脚と正面から基準面を作り、脚の移動へ連続的に追従させる。反転するモデル、180度ターン、蹴り上げ、ほぼ伸び切った状態を含めてテストする。膝トラッカーがある場合は割り当てと入力可否を明示する。
8. **手のひら補正にはモデルの手首→指先軸を使う。** v0.59.8の `HandTargetAdjustment` はVRIKの `wristToPalmAxis` で左右独立に回転する。ゲームの目標を直接回さず、計算中だけ補正目標へ差し替えて計算後に戻す。既定値0で位置を保持し、校正やフレームごとに回転が累積しないようにする。
9. **診断は同じ計算時点の値を使う。** MOD更新時の姿勢とVRIK計算直後の姿勢は別。フレーム、IKと脚の重み、到達率、膝角、足首と終端の位置・回転誤差を同時に保存する。v0.59.7以降は脚長・股関節から足首までの距離・要求される膝角も記録する。

## 描画とゲーム固有部分

HMDだけの非表示は体の専用レイヤーだけで判断すると小物が漏れる。v0.59.6の `AvatarHeadsetRenderGuard` はアバター配下のRendererをHMD描画中だけ抑止し、ネストした鏡・録画カメラでは復元する。ネストしたカメラの順序、例外、描画終了コールバックの欠落も考慮する。

ただし、カメラ管理API、VRIK所有者と更新順、アバターの読み込み・スケール調整、XR原点、MToonの照明はゲームごとに異なる。DanceDashへは各ゲームの実測・ログで対応を確認してから移植する。Synth Riders用のメンバー名やパッチ対象をそのままコピーしない。公開用パッケージにはゲームDLL・生ログ・個体番号全体を含めない。
