# Synth Riders Full Body

PC版 Synth Riders のアバターに、腰や足などのトラッカーの動きを反映する非公式MelonLoader MODです。ゲーム内のVRM選択画面から、トラッカーの割り当て・キャリブレーション・表示設定を操作できます。

**このガイドの対象：v0.59.9**

### v0.59.9の修正：標準姿勢での手のキャリブレーション

- **Tポーズは手のひらを下向き、Standing（直立）は腕を体の横へ下ろし、手のひらを体側へ向けてください。** アバターの掌面も同じ標準方向へ固定し、カウントダウン終了時にコントローラーとの回転の対応を保存します。鏡に合わせて手を不自然にねじる必要はありません。
- ゲーム標準の手にも自動補正が適用されます。手首を明示的に割り当てた場合は、そのトラッカーの校正を使用します。コントローラーの位置・照準・ゲーム操作は変更しません。指の骨格情報が不足するモデルでは、VRIKの手軸を使用し、それも取得できなければモデルの基準姿勢を保ちます。
- 「表示設定」の手の向きは微調整として残します。新しくキャリブレーションすると、入力を取得できた側の微調整は0度へ戻ります。シーン移動による校正復帰では維持します。コントローラーの欠測・取得元APIの変更時は、その手だけゲーム標準の回転へ戻します。
- 首・胸の姿勢は調査中です。今回のログでは頭の目標とボーンの位置誤差は小さいものの、首・胸の位置がなく、不自然な姿勢の原因までは特定できませんでした。基準姿勢とIK計算後の頭・首・胸・腰の位置関係をログへ追加しました。
- 更新後はゲームを再起動して、上記の標準姿勢で一度キャリブレーションしてください。実機確認は [チェックリスト](REAL_DEVICE_CHECKLIST.md) のPH1〜PH5を使用してください。実機での改善は未確認です。

### v0.59.8の修正と手の向きの調整

- 「表示設定」の**次のページ → 手の向き**で、左右の手のひらを15度ずつ回せます。キャリブレーション後、手を拍手の位置に置き、鏡を見ながら片手ずつ調整してください。反対へ回った場合は逆のボタンを使います。「手の向きを初期化」で0度へ戻せます。設定は保存され、再キャリブレーションは不要です。
- 補正対象はアバターの手の向きです。コントローラーの位置・照準・ゲーム操作は変更しません。全身追跡を有効にしてキャリブレーションした後に反映します。
- SteamVRとゲーム側HMDの頭の傾きの差が、追跡空間全体の傾きになる処理を修正しました。曲間ではゲーム側XR原点の移動だけを反映し、SteamVRとの登録を維持します。
- 表情ボタンを位置追跡の可否と切り離し、明示的な手首コントローラー割り当てがない場合はゲーム側XR入力を優先します。片手の入力元が変わっても、反対の手の表情を解除しません。取得元と対応ボタンを `Expression input:` に記録します。
- `SteamVR HMD pose appears stale` の警告は、ゲーム側の頭だけが動き、SteamVR側の頭が停止している疑いを示します。SteamVRのHMD接続と空間合わせを確認してください。床の傾きの混入を防いでも、外部ランタイム側の停止や初回の位置合わせをすべて解消できるわけではありません。
- 更新後はゲームを再起動し、一度キャリブレーションしてください。実機確認は [チェックリスト](REAL_DEVICE_CHECKLIST.md) のUT1〜UT5を使用してください。今回の提供ログはv0.59.5で、v0.59.6〜v0.59.7の修正も含まれます。

### v0.59.7の修正

- 足首の到達補正時に、膝へ約5.1度の曲がりを強制していた到達距離の制限を修正しました。脚長の限界では、骨を伸ばさず膝をまっすぐに解きます。実際に足を引き寄せる膝曲げは維持します。
- 今回のv0.59.5ログでは、足首補正が100%の142件すべてに5.1度の曲がりがありました。ただし、大きな膝曲げの記録もあり、その瞬間とユーザーの実動作を対応付けられていません。**前に出した脚が大きく曲がる症状まで解消したとは確認できていません。**
- ログに脚長・股関節から足首目標までの距離・その距離が要求する膝角度を追加しました。[チェックリスト](REAL_DEVICE_CHECKLIST.md) のKE1〜KE3で比較してください。v0.59.6のHMD非表示修正も含みます。

### v0.59.6の修正

- 「HMD内のVRM」をOFFにした時、通常レイヤーの小物が非表示から漏れる経路へ対応しました。アバター配下のRendererをHMD描画中だけ抑止し、鏡・配信カメラの描画時と描画終了時には元の状態へ戻します。後から追加された描画部品も定期的に再探索します。
- 対象の部品名・レイヤーとHMD描画イベントの実行状況を `VRM HMD render coverage:` へ記録します。今回のログでは設定の再適用は確認できましたが、翼付きリュック自体の描画情報がなく、症状の解消は実機確認が必要です。
- 更新後はゲームを再起動して「表示」→「HMD内のVRM」をOFF／ONにし、[チェックリスト](REAL_DEVICE_CHECKLIST.md) のHV1〜HV4を確認してください。この表示変更自体には再キャリブレーションは不要です。

### v0.59.5の修正

- 頭の入力をHMDから直接取得するよう変更しました。ゲーム側の中間目標が更新されなくなった場合も、首の動きを反映します。シーン復帰では元の校正値を引き継ぎ、復帰時に下を向いていてもその姿勢を新しい基準にしません。追加の頭トラッカーを割り当てた場合は、その入力を優先します。
- シーン復帰後にも頭の診断を記録します。既存ログだけでは下向き固定の瞬間を特定できていないため、実機での解消は確認が必要です。
- 表示設定を「バストショット固定」へ改称。**プレイ中・ポーズ中・曲開始処理中はゲームのカメラ設定を使用**します。それ以外は、設定・リザルトなどでもアバターを表示できれば固定を維持します。校正復帰待ちでは既存構図を保ち、復帰後に調整します。
- 更新後はゲームを再起動し、一度キャリブレーションしてください。今回の確認手順は [チェックリスト](REAL_DEVICE_CHECKLIST.md) のSC1〜SC4です。v0.59.4の足首補正も含みます。

### v0.59.4の修正

- 足首の目標が脚の届く範囲を超えたとき、足先を届かせるために足首が下向きになるケースへ対応しました。足先ボーンを終端にするモデルで、到達不足の脚だけを2ボーンで補正し、計測した足の向きを保ちます。
- 補正は到達限界付近でなだらかに適用します。到達可能な脚、足先ボーンを使わないモデル、追跡停止中の足は対象外です。足首＋足先の独立入力も反映します。
- **足の向きと接地は別に確認してください。** 骨長を伸ばさないため、目標まで届かない距離は残る場合があります。実機での改善は未確認です。更新後の手順は [チェックリスト](REAL_DEVICE_CHECKLIST.md) のAR1〜AR4を参照してください。

### v0.59.3の修正

- キャリブレーション時、ゲーム側の頭目標もモデルの頭ボーンへ合わせ直します。目の位置に合わせたモデルに対して、頭目標だけ高い位置に残る不一致を修正しました。頭の位置・首振りは、校正した位置と回転のオフセットを介して反映します。
- シーン移動では最初の頭の校正入力を再利用します。追加の頭トラッカーを割り当てている場合は、その入力を優先します。フルトラッキング停止時は元のゲーム目標へ戻します。
- v0.59.2のログでは、校正直後から骨盤の上方ずれ・脚の到達距離超過・足首の約50度のずれを確認しました。**つま先立ちの見た目が解消するかは実機確認が必要です。** 更新後に再キャリブレーションし、曲選択で15〜20秒静止して確認してください。[チェックリスト](REAL_DEVICE_CHECKLIST.md) のHC1〜HC4を参照してください。

### v0.59.2の診断改善

- 設定画面を閉じた曲選択・プレイ中にも、足首の回転・位置、脚の到達率、頭・骨盤の誤差を約10秒ごとに自動記録します。校正・校正復帰後の初回は約2秒後、設定画面を開いた間は約2.5秒ごとです。
- `Foot pose window:` に記録間の足首誤差・傾きの変動範囲を追加。一瞬だけ正常な足に戻る場合も、途中のずれを確認できます。

### v0.59.1の修正

- 足を上げたときに、校正済みの足位置を外側へ最大25cm押し出していた伸展補正を削除しました。トラッカーの位置を優先し、膝の曲がりを推測で減らさないようにします。足首＋足先の2台構成では引き続き両入力を使用します。

- 「表示」に「メニューでバストショット」を追加。ONにすると、ホーム・曲選択の配信／録画用カメラを、選択中のアバターの胸から頭が入る位置へ固定します。初期値はOFFです。
- 曲開始カウント・ロード・プレイ中はゲーム本来のカメラへ戻ります。設定は全アバター共通で保存します。実機での構図・描画確認は [チェックリスト](REAL_DEVICE_CHECKLIST.md) のMC1〜MC7を使用してください。

- 更新後は「表示」→「HMD内のVRM」を切り替えてください。この設定の変更に再キャリブレーションは不要です。実機ではHMDの両目、鏡、配信映像を確認してください。

### v0.58.1の修正

- モデルの基準姿勢の膝が横・後方へ張り出している場合に、その方向を曲げ方向として採用する処理を修正。更新後は問題のあったモデルを再キャリブレーションしてください。実機での改善確認は継続中です。

## できること

- 腰・左右の足を使ったフルトラッキング。頭・肘・手首・膝・足先にも追加のデバイスを割り当てられます。
- アバターを固定したTポーズ／Standing（直立姿勢）でのキャリブレーション。
- 検出したデバイスのシリアル番号・座標・動作状態の表示。
- 配信・録画用カメラの位置を、HMD内だけに水色の球で表示。
- アバターの影・内蔵ライト・HMD内での自分のアバター表示の切り替え。
- VRMの表情をコントローラーのボタンへ割り当てる操作。押下中のみ／押すたびの切り替えに対応。
- ゲームの言語設定に連動したUI表示（日本語・英語・フランス語・ドイツ語・スペイン語・韓国語・簡体字中国語）。

ノーツ判定やスコアは変更しません。異種コントローラーの割り当てはアバターとMODのUI用であり、ゲーム本体のノーツ判定用入力を置き換える機能はありません。

## 必要な環境

| 項目 | 必要なもの |
| --- | --- |
| ゲーム | Windows PC版 Synth Riders 3.x。Quest単体版は対象外です。 |
| MODローダー | MelonLoader 0.7.x（IL2CPP / net6）。本プロジェクトのビルド参照は0.7.3です。 |
| VR機器 | HMDと左右コントローラー。SteamVRでHMD・トラッカーを追跡できる環境。 |
| 基本のトラッカー構成 | 腰1台、左足1台、右足1台。足は装着位置に応じて足首／足先へ割り当てます。 |
| アバター | ゲームで読み込めるHumanoid（人型の骨格）のアバター。標準モデルも対象です。 |

Quest 3とVIVE Tracker 3.0／Ultimate Trackerなどを組み合わせる場合も、先に各機器をSteamVRで使える状態にしてください。**HMD・コントローラー・トラッカーの追跡空間を、外部の位置合わせツール等で揃えておく必要があります。** このMODは継続的な空間のずれ補正を行いません。Ultimate Tracker向けの任意の180度・水平位置補正も、外部ツールによる追跡空間の位置合わせを代替するものではありません。

機種名だけで対応を判断するのではなく、ゲーム起動後に `LIVE TRACKERS` で姿勢が取得できていることを確認してください。すべての機器の組み合わせ・アバター・ゲーム更新版で実機確認が済んでいるわけではありません。

### Ultimate Trackerで校正が失敗する場合

`pose=yes`は位置・回転を取得できたという意味で、HMDとトラッカーの空間合わせが正しいことまでは保証しません。Ultimate Trackerでは、先に [HTCのVIVE Space Calibratorの手順](https://www.vive.com/us/support/ultimate-tracker/category_howto/calibrating-the-trackers.html) で位置合わせを行い、SteamVR内で実物と表示位置が合っているか確認してください。HTCは、VIVE Space Calibratorと別の空間補正ツールを同時に有効にすると位置合わせへ影響すると案内しています。[HTCの対処方法](https://www.vive.com/ca/support/ultimate-tracker/category_howto/tracker-position-in-vr-and-real-world-dont-match.html)

v0.47.0では、足の左右逆（`Feet reversed`）と足幅不足（`Feet too close`）は警告のみです。Standing・Tポーズともに、この2つを理由に校正を停止しません。警告はカウントダウン中と完了後に表示され、追加の確認操作は不要です。`Calibration complete` が出たら鏡で動きを確認してください。自動で役割を交換することはありません。

`Feet reversed vs FRONT` は固定した正面に対して足の座標が逆という意味です。割り当ての取り違えだけでなく、追跡空間の不一致でも起こります。正面・視線・追跡状態・腰の高さ・静止状態のチェックと、Tポーズでの腕のチェックは引き続き行います。

正面と割り当てが正しいのに失敗する場合は、一度校正を試し、その起動の `Latest.log` を共有してください。`Calibration check [failed]` と `Calibration tracking [failed]` に、判定時の座標・向き・個体・追跡状態を記録します。詳しい調査結果は [Ultimate Trackerの調査メモ](docs/ULTIMATE_TRACKER_INVESTIGATION.md) を参照してください。

## 導入

1. ゲームを終了します。
2. Synth RidersにMelonLoaderを導入します。ローダーの導入方法は [MelonLoader公式Wiki](https://melonwiki.xyz/) を参照してください。
3. MelonLoaderを導入した状態でゲームを一度起動し、初期処理が終わったら終了します。
4. ビルド済みの `SynthRidersFullBody.dll` を、ゲームのインストール先にある `Mods` フォルダーへ配置します。

   ```text
   SynthRiders/
   ├─ Mods/
   │  └─ SynthRidersFullBody.dll   ← ここに配置
   ├─ MelonLoader/
   └─ UserData/
   ```

5. SteamVRで各デバイスの追跡状態を確認し、ゲームを起動します。
6. ゲーム内のVRM選択画面を開き、`フルトラッキング設定` と `キャリブレーション`（英語では `FULL BODY SETTINGS` と `CALIBRATE FULL BODY`）が表示されることを確認します。

MODの導入に使うのは `SynthRidersFullBody.dll` です。プロジェクト内の `Libs` フォルダーやUnity参照DLLは、`Mods` にコピーしません。`openvr_api.dll` は通常SteamVRのインストール先から自動検出します。

ソースコードからビルドする場合の出力先は `SynthRidersFullBody/bin/Release/net6.0/SynthRidersFullBody.dll` です。ビルド方法は [ビルド手順](docs/BUILDING.md) を参照してください。配布ZIPに含まれるライセンス・第三者表記のテキストも保管してください。

## 画面を開く・操作する

VRM選択画面に、次の2つの入口ボタンが表示されます。通常はゲームのスコア表示付近の位置に、独立したボタンとして配置されます。位置を取得できない場合はメニュー横に配置されます。

| 日本語表示 | 英語表示 | 用途 |
| --- | --- | --- |
| フルトラッキング設定 | `FULL BODY SETTINGS` | 設定画面を開きます。 |
| キャリブレーション | `CALIBRATE FULL BODY` | キャリブレーション画面を開きます。 |
| トラッカーの割り当て | `TRACKER ROLES` | 身体の部位とデバイスを対応付けます。 |
| トラッカーの状態 | `LIVE TRACKERS` | デバイスの状態を確認します。通常の設定画面の右側に表示されます。キャリブレーション中は手順案内に切り替わります。 |
| 表示設定 | `VISUAL OPTIONS` | カメラの目印、影、ライト、HMD内のアバター表示を切り替えます。 |
| 表情設定 | `EXPRESSIONS` | コントローラーのボタンに表情を割り当てます。 |
| トラッキング: 有効 / 無効 | `Tracking: ON / OFF` | キャリブレーション済みのフルトラッキングを一時的に有効／無効にします。 |
| Ultimate 180度補正: 有効 / 無効 | `Ultimate 180 correction: ON / OFF` | Ultimate Trackerの前後・左右の移動が両方逆の場合に180度補正します。切り替え後は再キャリブレーションします。 |

**コントローラーで項目を指し、その手のトリガーを押します。** ポインターは左が水色、右がピンクです。画面を開いた後や項目を押した後は、両手のトリガーを離してから次の項目を押してください。コントローラーの姿勢を取得できない場合は、項目を見る＋トリガーの操作へ切り替わります。

パネルは開いた位置に固定され、頭の動きには追従しません。両手トリガーやグリップの同時押しで画面を開く操作はありません。曲のプレイ中やVRM選択画面を離れた後は、設定・校正UIを表示しません。

### 共通の操作（v0.55.0）

- 左上の **戻る** は一段上へ戻ります。個体選択からは部位一覧へ、表情選択からはボタン一覧へ戻ります。トップ画面では無効です。
- 右上の **閉じる** は詳細画面を閉じます。未確定の個体選択は破棄され、保存済みの割り当ては維持されます。入口の2ボタンは残り、トリガーを離すと再び操作できます。
- 上部の **トラッカー／表示／表情／詳細** タブで画面を移動できます。キャリブレーションから開いたタブの「戻る」はキャリブレーションへ戻ります。「詳細」は設定のトップへ移動します。
- ピンクのボタンは開始・確定などの主要操作、矢印付きは画面移動、スイッチ付きはON/OFFです。Tポーズと直立は横並びで、選択中の方に印が付きます。
- 状態表示と空欄には押下反応がありません。無効な項目は灰色になり、キャリブレーション開始に必要なアバターやトラッカーの確認先が表示されます。
- 空白の長押しや、押したまま「閉じる」へ移動する操作では閉じません。**閉じるを指してから、新しくトリガーを押してください。**
- カウントダウン中はタブを隠します。「キャリブレーションを中止」「戻る」「閉じる」で中断できます。姿勢を変更する場合は中断してから選び直してください。

詳細画面を操作している間、入口ボタンは表示を保ちつつ入力を受け付けません。別の入口を使う場合は、詳細画面を閉じてトリガーを離してください。

### 文字・距離・操作フィードバックを調整する（v0.58.0）

「表示（Display）」→ **「UIの表示・操作（Panel & feedback）」** を開きます。

| 操作 | 内容 |
| --- | --- |
| 標準／大（＋15%） | 文字とボタンを一緒に拡大します。当たり判定も同じ大きさです。 |
| 近づける／遠ざける | 1.1〜1.8mの範囲で、0.1mずつ変えます。初期値は1.4mです。 |
| 現在地に位置を戻す | 現在の頭と入口ボタンの位置を基準に、詳細パネルを置き直します。 |
| 操作時の振動 | 対応する機器では、押した手にだけ短く振動します。初期値はON。 |
| 操作音 | 控えめなクリック音を鳴らします。初期値はOFF。 |
| サイズ・距離を初期値へ | 標準サイズ・距離1.4mへ戻します。振動・音の設定は保持します。 |

設定は全アバター共通で保存し、次回起動にも引き継ぎます。頭を動かしてもUIは追従しません。距離変更は画面を開いた時点の基準を使い、「現在地に位置を戻す」だけが現在位置を取り直します。キャリブレーション画面には移動操作を出さず、正面ターゲットも動かしません。

指しているボタンにシアンの枠、押下を受け付けたボタンに短い白枠が出ます。振動・操作音・白枠は**押下受付の通知**です。保存やキャリブレーションの成功は、各結果表示で確認してください。視線操作では振動しません。未対応の機器でもボタン操作は使えます。

長いキャリブレーション結果は、右側の「前のページ／次のページ」で全文を読めます。ページ数が1の一覧ではページ送りを隠します。7言語での実際の文字の収まり、音量・振動の強さは実機確認が必要です。

### Ultimate Trackerの前後・左右への動きが逆の場合

1. `FULL BODY SETTINGS` の `Ultimate 180 correction` を **ON** にします。
2. `CALIBRATE FULL BODY` を開き、StandingまたはTポーズで再キャリブレーションします。
3. 片足を前・横へ動かし、同じ方向へ動くことを鏡で確認します。続いて腰の移動・回転も確認します。

補正の初期値はOFFです。ONでは、SteamVRが `VIVE Ultimate Tracker` として報告する機器の位置と回転を、校正時に固定した中心の周りで水平に180度回転します。腰・足・膝など、割り当てたUltimate Trackerすべてへ適用します。QuestのHMD・コントローラーやVIVE Tracker 3.0には適用しません。前後だけが逆の現象にはこの設定は対応していません。

v0.49.0から、腰もUltimate Trackerの場合は、**校正開始時に直立したHMDの真下へ腰の水平位置を合わせる**処理を追加しています。同じ移動をUltimate Tracker全体へ適用し、足や腰の回転に大きな空間の位置ずれが混ざることを防ぎます。追跡中は基準を固定するので、頭を動かしてもその位置合わせは変わりません。校正を開始するときから正面を向いて直立してください。腰が対象外・未追跡の場合は、この水平位置合わせを行いません。

この水平補正は試験的な機能です。計算テストは実行済みですが、Ultimate Tracker実機での改善確認は完了していません。

設定は全アバター共通で保存され、シーン移動でも引き継ぎます。切り替えると古い校正は解除されます。`LIVE TRACKERS` の座標は引き続きAPIの生座標です。補正後の動作はアバター・部位マーカーで確認でき、ログの `Ultimate Tracker 180 correction` と `raw / world` にも記録されます。

## UIの言語

v0.54.0から、**Synth Riders本体で選択した言語**に合わせてMODのUIも切り替わります。対応言語は日本語・英語・フランス語・ドイツ語・スペイン語・韓国語・中国語（簡体字）です。MOD側での言語設定や追加の翻訳ファイルの配置は不要です。

- 日本語の呼称はゲーム本体に合わせて「キャリブレーション」です。

このREADMEの以降の操作説明では、従来の英語ラベルを併記・使用しています。日本語での入口は上の対応表を参照してください。初回起動時に言語を取得できない場合や未対応の言語では英語表示になります。シーン移動中の一時的な未取得では直前の言語を維持します。

各言語の切り替え・翻訳の書式・フォント選択は自動テスト済みです。VR実機での文字欠け、読みやすさ、訳語の自然さは確認が必要です。

## トラッカーを割り当てる

### 最初は腰と左右の足を設定する

1. `FULL BODY SETTINGS` → `TRACKER ROLES` を開きます。
2. 設定したい部位を選びます。
3. その部位に付けたトラッカーを軽く動かし、一覧の `MOVING` とシリアル番号で個体を確認します。
4. 個体を選ぶと、部位ごとの「現在 → 変更後」を表示します。内容を確認して **「変更を適用（Apply changes）」**を押します。時間制限はありません。
5. 腰・左足・右足を設定します。項目が見えない場合は「前のページ／次のページ」で移動します。先頭・末尾では該当ボタンが無効になります。
6. 「キャリブレーションへ」から姿勢合わせへ進みます。

**Left / Rightは、装着している自分から見た左右です。鏡の中の見た目で判断しないでください。** HMDに付けた位置合わせ用トラッカーを `Waist` に割り当てないようにしてください。外部の空間補正にだけ使用する個体は、このMODでは未割り当てのままで構いません。

| UIの部位名 | 装着・反映先 |
| --- | --- |
| `Waist` | 腰 |
| `Left ankle` / `Right ankle` | 左／右の足首 |
| `Left toes` / `Right toes` | 左／右の足先 |
| `Head` | 頭。未設定ならゲームのHMD入力を使います。 |
| `Left wrist` / `Right wrist` | 左／右の手首。未設定ならゲームの手の入力を使います。 |
| `Left elbow` / `Right elbow` | 左／右の肘の曲がる位置 |
| `Left knee` / `Right knee` | 左／右の膝の曲がる位置 |

- 1つの個体を複数の部位には割り当てられません。別の部位へ選ぶと、以前の部位から移動します。
- 解除するには、部位を選んで `CLEAR / USE GAME DEFAULT` →「変更を適用」と進みます。腰や足の必須入力を解除した場合は、そのままではフルトラのキャリブレーションはできません。
- 割り当てを変更した後は、再キャリブレーションが必要です。確認前の「変更をキャンセル」・戻る・タブ移動・閉じるでは、変更案を破棄して現在の設定とキャリブレーションを維持します。
- 個体一覧は取得元・識別子の順です。選択画面を開いている間、切断した行は `LOST` として残り、新しい接続は末尾へ追加します。候補が切断された場合は、キャンセルして選び直してください。
- シリアル番号がない個体の割り当ては、その接続中のみ有効です。再接続・再起動後は割り当て直してください。

### Ultimate補正などの変更

「詳細」のUltimate 180補正は、**前後と左右の移動が両方逆の場合**に使います。現在値と変更後の値を確認して「変更を適用」を押すと、再キャリブレーションが必要になります。キャンセルでは変更しません。影・ライト・カメラ表示・表情の設定は再キャリブレーション不要です。

### AUTOを使う場合

1. 鏡へ体を向け、足を軽く開いて立ち、「AUTO：割り当て案を作成」を押します。
2. 「AUTOの提案（未適用）」を確認します。この時点では保存設定も追跡も変更しません。
3. 修正したい部位を選び、個体を動かして選択し、「変更案に反映」を押します。解除も提案に反映できます。
4. 「提案を確認」で変更一覧を表示し、「変更を適用」で確定します。キャンセル・戻る・閉じる・タブ移動では提案全体を破棄します。
5. 「キャリブレーションへ」から姿勢を合わせます。

`AUTO` は、**未設定の腰・足首・足先に候補を入れる機能**です。既存の割り当ては上書きせず、頭・肘・手首・膝は自動設定しません。判別できない部位は未設定になります。提案は必ず個体を動かして確認し、必要なら適用前に修正してください。

### 足首と足先の両方に付ける場合

足首・足先の個体選択中は、右側に装着位置の説明図を表示します。片足に2台付け、`ankle` と `toes` に別々の個体を設定できます。足首を位置の基準にし、足先の入力も使って向きを反映します。足先だけに1台付ける構成では、`toes` だけを設定できます。

片足1台の場合（`ankle` または `toes` の片方だけ）、足首とつま先を別々には計測できません。v0.50.0から、足全体はトラッカーへ追従させ、足首に対するつま先の角度は校正時の姿勢に保ちます。足裏が合っているのにつま先だけが反る動作を抑えるための補正です。足首と足先に別々の2台を割り当てた場合は、独立した足先の動きを引き続き反映します。

追加部位には、アバター側の対応するIK（骨格を動かす仕組み）が必要です。足首・足先を同時に使う場合は、足先ボーンも必要です。条件を満たさない場合は校正画面に理由が表示されます。

### LIVE TRACKERSの見方

| 表示 | 意味 |
| --- | --- |
| `SteamVR` / `Unity XR` | デバイス情報の取得元 |
| `#`番号・`S/N` | デバイス番号とシリアル番号 |
| `X / Y / Z` | 取得元の追跡空間での座標（メートル）。アバター上の座標ではありません。 |
| `m/s` | 移動速度 |
| `MOVING` | 移動または回転を検出した個体 |
| `Tracking lost` / `LOST` | 個体は見つかっていますが、姿勢を取得できない状態 |

通常表示は、取得元・個体番号・機器名・`TRACKED / MOVING / LOST`を3台ずつ表示します。動作中のカードは強調しますが、動作量で並び替えません。

右上の **「詳細表示（Show details）」** をONにすると、1台ずつ大きなカードで生座標と速度も確認できます。前へ／次へでHMD・コントローラーを含む全個体を確認できます。異なるAPIの生座標どうしは、そのまま距離や位置として比較しないでください。

この一覧に推測した身体の部位名は表示しません。実際の割り当ては `TRACKER ROLES` で確認します。同じ個体がSteamVRとUnity XRの両方に見える場合は、取得元ごとに表示されます。全台が見えない場合は「前のページ／次のページ」で移動してください。

## キャリブレーション

キャリブレーションは、トラッカーとアバターの身体の位置・向きを合わせる操作です。

### 4段階の流れ（v0.56.0）

| 段階 | 操作・表示 |
| --- | --- |
| 1. 準備確認 | アバター・腰・左右足の状態を確認します。「未割り当て」「追跡喪失」「重複」は「割り当てを確認」から直してください。設定済みの個体を毎回割り当て直す必要はありません。 |
| 2. 姿勢選択 | 「次へ：姿勢を選ぶ」で進み、Tポーズ／直立を選びます。右側の説明図と鏡の固定アバターを参考にします。 |
| 3. カウントダウン | 開始を押し、正面の目の高さの点を見ます。Tポーズは5秒、直立は3秒です。設定一覧・タブは隠れ、短い姿勢案内が表示されます。 |
| 4. 動作確認 | 成功したら鏡で腰と左右の足を動かします。「完了」で閉じるか、「やり直す」で準備へ戻れます。失敗時は理由が表示されます。 |

準備確認を開いただけでは、既存のキャリブレーションを解除しません。**姿勢選択へ進むと以前のキャリブレーションを解除します。** 以後に中止した場合は、新しくキャリブレーションを完了するまでゲーム標準の頭・手の追跡になります。保存済みのトラッカー割り当ては維持します。

### 正面と立つ位置

1. 使用するアバターを選び、合わせたい場所で直立して `CALIBRATE FULL BODY` を押します。
2. 準備確認でアバター・腰・左右足が「準備OK」になったら「次へ：姿勢を選ぶ」を押します。足には主入力として使う足首／足先も表示します。追加で割り当てた部位に欠測がある場合は、下部の理由を確認してください。
3. **床の `FRONT` 矢印の方向へ、顔と身体を向けます。** 正面ターゲットは準備確認から表示され、床の矢印は腰・左右足の追跡を取得した後に表示されます。

`FRONT = MIRROR` の場合は、ゲームの `Toggle mirror` で表示する鏡の方向が正面です。MODはキャリブレーション中と成功後の動作確認で、ゲームの鏡を一時表示します。鏡を取得できない場合は `FRONT = THIS ARROW` となり、画面を開いた瞬間の水平な視線方向を正面に固定します。

パネルや入口ボタンの方向が正面とは限りません。「やり直す」ではパネル位置と正面を取り直しません。立つ位置を変えた場合は、右上の「閉じる」で閉じ、入口の `CALIBRATE FULL BODY` をもう一度押してください。

### Tポーズでキャリブレーションする（初期モード）

1. 姿勢選択で `T-pose` を選びます。アバターの両腕が水平に広がり、その姿勢で固定されます。
2. 両足を床に置き、軽く開いて正面を向きます。
3. `START T-POSE CALIBRATION` を押します。この時点で腕を広げておく必要はありません。
4. **5秒の間に両腕を肩の高さで左右へ広げ、手のひらを下へ向けます。** 手を交差させず、左右の高さを揃えてください。
5. 正面のターゲット点を見て、0になるまで静止します。足元を見る必要はありません。点がオレンジになったら姿勢の案内を確認してください。
6. 成功すると姿勢固定が解除されます。鏡で腰と左右の足を動かし、問題なければ「完了」を押します。合わせ直す場合は「やり直す」を押してください。

鏡では水色の骨格ガイドと、両手の実際の位置を示すピンクの輪も確認できます。姿勢選択・カウントダウン中のアバターは固定され、自分の動きに追従しないのが正常です。

### Standingでキャリブレーションする

姿勢選択で `standing`（直立）を選ぶと、説明図とアバターが腕を下げた姿勢になります。

1. 腕を体の横へ下ろし、手のひらを体側へ向けます。両足を軽く開いて直立します。
2. `CALIBRATE STANDING` を押します。
3. 正面のターゲット点を見ながら **3秒間** 静止します。
4. 成功後は鏡で動きを確認し、「完了」か「やり直す」を選びます。

Standingでも腰と左右足の追跡が必要です。大きく下を向く、トラッカーが動き続けるなどの場合は失敗します。足の左右逆・足幅不足は両モードとも警告に留め、他の条件を満たせばキャリブレーションを続けます。警告は動作確認画面にも残します。

### 中止・失敗・やり直し

- 「キャリブレーションを中止」または「戻る」で準備確認へ戻り、カウントダウンと固定姿勢を解除します。「閉じる」は詳細画面も閉じます。
- 姿勢選択から別タブへ移動しても固定姿勢を解除し、戻ったときは準備確認からになります。勝手に計測を再開しません。
- 失敗時は右側に理由が表示されます。「やり直す」で準備から確認するか、「割り当てを確認」で機器を確認してください。
- 成功後の「完了」は詳細画面を閉じる操作です。身体との一致が自動的に確認されたという意味ではないため、鏡で実際の動作を確認してください。
- キャリブレーション途中の中止では、仮の姿勢とサイズを元へ戻します。

### モデルのサイズについて

モデルの高さは校正中にユーザーへ合わせて均等に調整します。小さいモデルは拡大、大きいモデルは縮小し、体型の比率を保ちます。VRMファイル自体は変更しません。体型やトラッカーの装着位置による差は残るため、足裏と床が厳密に一致するとは限りません。サイズにかかわらず、まず直立し、両足を床へ置いた状態で校正してください。

## 配信カメラ・アバターの表示設定

`FULL BODY SETTINGS` → `VISUAL OPTIONS` から変更できます。これらの操作にキャリブレーションは不要です。

| 設定 | 動作 |
| --- | --- |
| `Camera guide in headset` | `ON`で配信・録画用カメラの位置に水色の球と `CAPTURE CAMERA` を表示します。目印はHMD向けで、配信映像には表示しない設計です。初期値は`OFF`です。 |
| `VRM cast/receive shadows` | `OFF`でアバターが影を落とす・受ける処理を無効にします。初期値は`ON`です。 |
| `VRM lights` | `OFF`でアバターに含まれるライトを無効にします。ライトを含まないモデルでは効果がありません。初期値は`ON`です。 |
| `VRM in headset` | 自分のアバターをHMD内に表示するか切り替えます。配信カメラ側のアバター表示は維持します。 |
| `Fixed bust shot`（バストショット固定） | プレイ外でアバターが見えている間、配信／録画用カメラを正面のバストショットに固定します。プレイ中はゲームの設定を使用。初期値は`OFF`です。 |

影・ライトの設定はアバターを対象とし、ステージ全体は変更しません。軽くなる程度はモデルによって異なり、重いシェーダーやポリゴン数を減らす機能ではありません。

### HMDだけでアバターを非表示にする

`VRM in headset: OFF` にすると、現在のVRMの非表示希望値を保存します。VRMごとの設定なので、別のVRMでは個別に選択してください。鏡や三人称の配信映像では、引き続きアバターを確認できます。

v0.53.0では、同じアバターの設定がゲーム側で再読み込みされた場合も保存値を再適用します。HMDカメラの交換や描画マスクの変更も検出し、ゲームの一人称表示APIを呼び直します。読み込み中は切り替え操作を受け付けません。MODで保存した値は、ゲーム側で後から変更された値より優先されます。

設定を切り替えても見え方が変わらない場合は、`VRM headset visibility applied.`、`Saved VRM headset visibility reapplied.`、`VRM headset visibility update failed:` の前後をログから共有してください。適用先のアバター、HMDの個体ID、`visible`、描画マスク、`hide(view/avatar)`（共通／個別の非表示フラグ）の変更前後を記録します。ログの適用完了はゲームAPIの完了を示すため、HMD両目・鏡・配信映像での確認も必要です。

### プレイ外のカメラをバストショットにする

1. ゲーム側で三人称・ダイナミック・観戦者・Custom Cameraなど、配信／録画用カメラを有効にします。
2. 「表示」→「バストショット固定」を`ON`にします。この設定の変更だけではキャリブレーションのやり直しは不要です。
3. アバターが表示されるホーム・曲選択・設定画面などで、PC画面や録画の構図を確認します。初回の対象カメラ描画後、状態が「バストショット: 固定中」になります。

アバターの頭・胸・肩幅と映像の縦横比から、正面の位置と画角を決めます。位置はその場に固定され、頭を揺らしたり体を動かしたりしても追いかけません。立ち位置を変えて画面から外れた場合は、OFF→ONで構図を取り直してください。アバター・体格・出力の縦横比が変わった場合や、曲からメニューへ戻った場合も取り直します。

曲開始カウント、曲のロード、プレイ中・ポーズ中はゲーム側のカメラ設定を使用します。ホーム・曲選択・設定・リザルトなどでは、アバターが表示可能なら固定を続けます。HMD内だけVRMを非表示にしても、配信側の固定は継続します。

キャリブレーションの姿勢プレビューや保存校正の復帰待ちでは、同じアバターの既存構図を保ち、完了後に取り直します。まだ構図がない場合は姿勢が確定するまで待機します。HMDの視点、鏡、LIV、一人称、カメラOFFは対象外です。カメラの目印を併用すると、固定した位置に水色の球を表示します。

構図が切り替わらない場合は、表示設定の状態とログの `Menu bust camera:` を確認してください。「カメラ描画待ち」のままなら、ゲーム側でそのカメラが出力されているか確認してください。大きな髪・帽子など、骨格より外側の装飾は画面からはみ出す場合があります。

### カメラの目印を探す

1. ゲーム側で三人称・ダイナミック・観戦者・Custom Cameraなど、配信／録画用カメラを有効にします。
2. `Camera guide in headset: ON` にします。
3. `VISUAL OPTIONS` のカメラ検出状態と、方向・距離の表示を確認し、その方向の水色の球を探します。

一人称・カメラOFFでは対象の球を表示しません。LIVのカメラには球を重ねず、LIV側の目印を使います。カメラを検出できない場合や表示処理に問題がある場合は、画面の状態表示とログを確認してください。

v0.52.0では、ゲームの空き描画レイヤーを必要とせず、HMDカメラを描画先に指定して目印を表示します。以前のログに `No unused Unity layer` が出ていた場合も、この制約で表示が止まることはありません。

モードを切り替えると対象を選び直し、動くカメラの位置へ球が追従します。設定画面には `Spectator: Cam #123` のようにモード・カメラ名・実行中の個体IDを表示します。内部のモード名（`ThirdPersonSwing`、`Cinematic`など）はゲームUIの表記と異なる場合があります。`Waiting for ...` は対象の読み込み待ち、`candidates` は複数候補があり選択中の出力を確定できない状態です。

見えない場合は一度OFF→ONにして再検出してください。ログの `Capture camera diagnostics:` には対象個体、HMD、カメラの階層、位置、描画先、文字の準備状態、エラーを記録します。文字の生成に失敗した場合も、水色の球の表示は継続します。

## コントローラーで表情を変える

v0.51.0で追加した機能です。初期状態はOFF・未割り当てです。フルトラのキャリブレーションを行う前でも使用できます。

1. VRMを選び、ゲームの `toggle mirror` で鏡を表示します。
2. `FULL BODY SETTINGS` → `EXPRESSIONS` を開き、`Expressions: ON` にします。
3. 割り当てたいボタンを選びます。`Show RIGHT / LEFT controller` で左右を切り替えます。
4. 表情を選びます。`Next expressions` で次のページに進み、`[Selected]` が付いた項目が現在の割り当てです。
5. `Mode` を選び、`Hold`（押している間だけ）か `Toggle`（押すと保持、もう一度押すと解除）を指定します。
6. 割り当てたボタンを一度離してから押し、鏡で確認します。`Close panel` 後や曲のプレイ中も操作できます。

| ボタン表示 | Quest 3での操作 |
| --- | --- |
| `Left primary` / `Left secondary` | 左のX / Y |
| `Right primary` / `Right secondary` | 右のA / B |
| `Left grip` / `Right grip` | 左／右のグリップ |

SteamVRコントローラーでは主ボタン（Aまたはパッド押下）、副ボタン（アプリケーションメニュー）、グリップを読み取ります。使える入力は機種・ランタイム・入力設定によって異なり、読み取れないボタンは選択画面の下に `Button unavailable` と表示します。手首にコントローラーを割り当てている場合はその個体を優先します。

- `Unassigned` でそのボタンの割り当てを解除できます。`Reset expression` を割り当てると、MODで保持している表情を解除できます。
- 同時に複数のHoldを押すと後から押した表情が優先され、離すとまだ押している表情へ戻ります。HoldはToggleで保持した表情にも一時的に優先します。
- **ゲーム本体にも同じボタン入力が届きます。** ゲーム側の操作・標準の表情処理が重なる場合は、別のボタンを使ってください。
- 表情設定以外のMOD設定画面や校正中は解除・停止します。シーン変更、アバター変更、入力切断でも解除し、再開には一度ボタンを離してから押し直します。
- VRM 0.x / 1.0の表情APIに登録された表情を使います。表情のないモデルでは `No VRM expressions found`、別モデルに存在しない割り当ては `Unavailable on this avatar` と表示し、その表情を適用しません。モデルに新しい表情を作る機能や、顔・音声のトラッキング機能は含みません。

## 設定の保存とシーン切り替え

設定はゲームのインストール先の `UserData/SynthRidersFullBody.json` に保存されます。通常はゲーム内UIだけで設定できます。

| 項目 | 保存・引き継ぎ |
| --- | --- |
| トラッカーの割り当て | 全アバター共通。シリアル番号がある個体は次回起動時も復元します。シリアル番号がない個体は再接続・再起動後に再選択が必要です。 |
| Tracking、影、ライト、カメラガイド、バストショット固定 | 全アバター共通。シーン切り替え・再起動後も設定を引き継ぎます。 |
| Ultimate 180 correction | 全アバター共通。シーン切り替え・再起動後も設定を引き継ぎます。設定キーは `UltimateTrackerRotate180`。 |
| HMD内のアバター表示 | アバターごとに保存し、読み込み後に再適用します。 |
| 表情の有効／無効・ボタン割り当て・Hold/Toggle | 全アバター共通。シーン切り替え・再起動後も設定を引き継ぎます。標準表情はVRM 0.x / 1.0の対応名を使用し、独自表情は同名のモデルで使用します。操作中の表情そのものはシーン移動時に解除します。 |
| キャリブレーション結果 | 今回のゲーム起動中のみ保持します。同じアバターのシーン移動では、準備が整い次第、復帰を試みます。 |

**次の場合は再キャリブレーションしてください。**

- ゲームを起動し直した。
- 別のアバターへ変更した。
- トラッカーの割り当てや装着位置・向きを変えた。
- `Ultimate 180 correction` を切り替えた。
- v0.48.0からv0.49.0へ更新した（補正ONのままで再校正してください）。
- SteamVRの原点や、外部ツールの追跡空間の位置合わせを変更した。
- 画面に再校正が必要と表示された。

シーン読み込み中は、一時的に頭と手だけの追跡になる場合があります。腰の追跡を失った場合もゲーム標準の動きへ戻し、復帰後は元の校正を使ってフルトラへ戻します。

## 困ったときは

| 症状 | 確認すること |
| --- | --- |
| 入口ボタンがない | VRM選択画面を開いているか確認してください。プレイ中は非表示です。ゲームの `Mods` にDLLが1つだけあるか、`Latest.log` にMOD名とバージョンが出るかも確認します。 |
| 項目を押せない | いったん左右のトリガーを離し、指している手のトリガーを押してください。ポインターが項目に重なる位置で操作します。 |
| パネルを閉じにくい | 両手のトリガーを離し、右上の `Close panel` を指して新しく押します。空白の長押しでは閉じません。コントローラーの姿勢を取得できない場合は、右上を見てトリガーを押してください。 |
| `HMD: missing` / トラッカーが見えない | SteamVRで機器が追跡中か確認します。`LIVE TRACKERS` の個体名だけでなく、姿勢が更新されているかも確認してください。 |
| 台数は揃っているのに校正できない | `TRACKER ROLES` で腰と左右足の割り当てを確認します。台数が揃っていても、自動では役割を確定しません。 |
| `Avatar: missing` | ゲームでアバターを選び、読み込みを待ちます。人型の骨格を持つモデルかも確認してください。 |
| `Check WAIST role` / 腰が頭に引っ張られる | HMD装着のトラッカーを腰に選んでいないか確認します。腰だけを動かして個体を特定し、割り当てを直して再校正します。 |
| 左右の足が逆・ターン後にずれる | 装着者基準の左右、床の`FRONT`矢印、各デバイスの追跡空間を確認します。装着ずれや外部の空間合わせを直した後は再校正してください。 |
| `Calibration failed` | 画面下部の理由を確認します。足を軽く開く、目の高さの点を見る、トラッカーを静止させる、Tポーズでは両腕の高さを揃えることを確認します。 |
| 校正後に追従しない | `Tracking: ON` と `Calibration complete` を確認します。腰・左右足が追跡中か確認し、鏡で動きを見てください。 |
| シーン移動後に頭と手だけになる | アバターの読み込みと追跡復帰を待ちます。戻らない場合はVRM選択画面で状態を確認し、再校正してください。繰り返す場合はログを添えて報告してください。 |
| モデルが大きすぎる・姿勢が崩れる | 正しい腰・足を割り当て、直立した状態で再校正します。別のアバターでも起きるかを確認し、改善しなければモデル名とログを添えてください。 |
| カメラの球がない | ゲーム側の配信用カメラとガイドがONか確認します。一人称・OFF・LIVでは球は表示しません。`VISUAL OPTIONS` の状態・方向・距離を確認してください。 |
| ゲームが重い | `VRM cast/receive shadows` と `VRM lights` をOFFにして比較します。効果が小さい場合は別の軽いアバターでも確認してください。 |

## 更新・アンインストール

**更新：** ゲームを終了してから、`Mods/SynthRidersFullBody.dll` を新しいDLLで置き換えます。古いDLLを別名で同じフォルダーに残すと重複して読み込まれるため、`Mods` の外へ移してください。設定ファイルは残せます。起動後はキャリブレーションを行います。

**削除：** ゲームを終了して `Mods/SynthRidersFullBody.dll` を削除します。設定も消す場合は `UserData/SynthRidersFullBody.json` を削除します。HMD内のアバター表示はゲーム側の設定にも反映されるため、必要ならゲームのアバター設定で戻してください。

**設定を初期化：** ゲームを終了し、`UserData/SynthRidersFullBody.json` を別の場所へバックアップしてから元のファイルを削除します。次回起動時に既定設定を作成するので、トラッカーの割り当てと校正をやり直してください。

## 不具合を報告するとき

ゲームのインストール先にある **`MelonLoader/Latest.log`** を、問題が起きた起動のものとして保存し、次の情報と一緒に共有してください。

- MOD・ゲーム・MelonLoaderのバージョン。
- HMD、トラッカー、コントローラーの機種と台数。HMD装着の位置合わせ用トラッカーの有無。
- アバター名、部位の割り当て、T-pose／Standingのどちらを使ったか。
- 発生した画面・シーン、再現する操作手順、期待する動作と実際の動作。
- 可能なら画面のスクリーンショットまたは動画。
- カメラの問題では、ゲーム側のカメラモードと `VISUAL OPTIONS` の状態表示。

公開Issueへ添付するログでは、シリアル番号・ユーザー名・個人情報を含むパスを伏せてください。同じ個体には同じ伏せ字を使うと、割り当ての問題を確認しやすくなります。設定ファイルにも個体番号が保存されるため、公開するときは同様に確認してください。

詳しく動作を確認する場合は [実機確認チェックリスト](REAL_DEVICE_CHECKLIST.md) を参照してください。過去の変更履歴・ビルド手順・技術情報は [開発メモ](docs/DEVELOPMENT_NOTES.md) にまとめています。

今後のUI改善と、既知の問題・調査対象・完了条件は [開発項目・既知の問題](docs/DEVELOPMENT_BACKLOG.md) にまとめています。
